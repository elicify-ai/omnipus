# Relay replacement admission — 2026-09-07

Source tracing found that ingest installation, track attachment, feed termination, connection clearing, session close, and the current-video-boundary query hold `Session.mu` while acquiring a media forwarder's writer lock. The writer lock deliberately spans external RTP and sender-report writes so ownership changes cannot let an old source consume a successor's sequence or timestamp range. A stalled write therefore indirectly blocks unrelated session control and statistics when one of these control paths waits for that lock.

The required change preserves the writer boundary. Installation must wait cancelably outside `Session.mu`, revalidate the exact candidate reservation after admission, and only then replace the installed peer and retire old feeds. Canceled admission must leave the old peer/feed intact. Track attachment must similarly acquire writer ownership before revalidating its peer and publishing its feed. Cleanup must capture its exact old feed, release `Session.mu`, and retire only that captured identity; delayed cleanup cannot retire a successor. Close must cancel signaling and start transport cleanup before waiting for writer retirement.

The video-boundary query must continue using the successful-forward timestamp high-water. Ingress receipt evidence is not proof that a frame was forwarded and cannot authorize a displayed-frame boundary. Its session snapshot, forwarder lookup, and final identity revalidation must not nest `Session.mu` around a writer wait.

GitNexus impact: attach has one direct caller (LOW), endFeed one direct/two total (LOW), clear two direct/three total (LOW), and Close zero mapped callers (LOW). The index's older public HandleIngestOffer entry maps zero callers (LOW); the newer private handleIngestOffer and CurrentVideoBoundary are absent (UNKNOWN coverage), so the source trace, not an empty graph result, establishes their scope.

Receipt publication, receipt serials, and Stats implementation remain owned by the media lane and are not part of this change.

Loss notification must run before draining a blocked writer, once the dead peer has already been cleared and its installed lifetime canceled. The optional identity-qualified callback carries the original installed binding, offer, generation, and target. A coherent retained installation snapshot also samples the ingress receipt serial under the short session lock; this is a recovery-progress baseline, not a displayed-frame acknowledgement. The capture-session adapter separately qualifies the callback against current binding/frame state. Three new notification/snapshot regressions failed against compatibility shells in 1.950 seconds: notification waited for the writer, immutable identity delivery was absent, and the snapshot omitted the already accepted packet serial. Their implementation is included in the 2.160-second focused green run. The retained installed tuple is stamped at successful installation, before OnTrack, and is independent of newer pending offer reservations.

The first mutation batch caught all eleven deliberate faults: holding the session lock while waiting, ignoring caller cancellation, skipping reservation revalidation, retiring a successor feed, retaining the old installed lifetime, skipping track identity revalidation, trusting a stale boundary snapshot, delaying loss notification until writer drain, confusing installed and pending offer IDs, waiting on the writer for the recovery snapshot, and corrupting the original loss frame identity. The correction classifies canceled writer waits under the short session lock and preserves exact supersession errors before generic cancellation; it does not wait for writer ownership. The corrected focused selection passed in 1.891 seconds; the twelfth deliberate fault removed supersession classification and reproduced both existing failures. The final restored full relay race/shuffle run passed all 172 leaf cases in 69.947 seconds on 2026-09-08, with zero skips, failures, or race warnings.

Residual boundary: acquiring both media ownership locks is necessary before atomic replacement. If audio is stalled after video ownership was acquired, video writes wait until admission cancels or audio drains. Session control and statistics remain responsive; this change does not promise uninterrupted media during every replacement wait. A successful-forward boundary query can itself wait for a writer, while releasing the session control lock and rejecting a stale result afterward.
