# Viewer signaling integration tests

The production offer handler must use the original attachment captured synchronously at dispatch, keep temporary negotiation cancellation separate from the established peer's source lifetime, and publish only the exact confirmed capture/generation and offer ID. It must use the context input constructor and original-context registration, with no fallback to a newer attachment or an unfenced relay. These expectations follow the approved browser frame-generation protocol and the verified request/cancellation defects in the media test plan.

The first gateway boundary tests keep browserConnState real: replacing a request cancels only prior negotiation; completing old work cannot cancel newer work; completing accepted negotiation keeps the committed peer and original attachment; replacement attachment cannot be resolved or committed by old work; invalidation cancels pending work; and uint64 dispatch epoch exhaustion cannot wrap. No transport is mocked because these are in-memory admission rules. Callable incomplete helpers initially expose the existing late-resolution/uncancelable behavior for the first red.

The handler tests will leave parsing, manager/panel resolution, capture state, request dispatch, frame waiting, registration and scoped answer publication real. A relay boundary may control negotiation completion; existing real Pion request/preparation tests cover transport admission and original input lifetime. Assertions will distinguish queue admission from actual delivery/presentation, and maintain initial empty capture claims versus strict supplied claims. No source-string checks, no exported test seams, and no new wire fields.

Capture stop must end temporary negotiation as soon as CaptureSession.Done closes, even while its shutdown control send is blocked before relay teardown. The same handler fixture will block that external control send, assert prompt handler completion and no writable answer, and verify the original attachment remains alive. Cleanup explicitly releases both external boundaries. This tests the real stop ordering, not a simulated relay-close signal.

The established data-channel error callback is qualified by its exact source lifetime, not by a later signaling attempt's epoch. A replacement that is merely pending must not silence errors from the still-installed peer. The handler fixture will invoke the real stored callback with the peer source context, verify its scoped queued error, and then cancel that source to prove writer-time rejection. Relay tests separately prove when that stable context is canceled by actual peer replacement.

The integrated handler must enqueue matching confirmed health before waiting for answer-queue capacity. A full real critical queue will hold the answer while the replaceable health slot remains available; the test asserts original capture/generation/target/CSS metadata and source scope there, then cancels the attachment and drains the handler. This proves enqueue ordering and cancellation, not network delivery order.
