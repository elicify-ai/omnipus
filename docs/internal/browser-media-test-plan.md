## Wave 3: input source lifetime

Specification: original attachment lifetime and peer replacement/close must cancel legacy data-channel input before an old callback can be interpreted as the new attachment sharing its viewer ID. This is the parent-approved `ContextInputSink` / `NewSessionWithContextInput` / `HandleViewerOfferHandleContext` API contract; existing wrappers retain compatibility. Context cancellation is persistent for the peer, never the temporary offer-handler duration.

Test boundary: real Pion encoder/viewer peers and relay, plus the real queue with only the final sink blocked at its process edge. Cases: parent attachment values reach the sink; returning from negotiation leaves the peer context live; attachment cancellation, viewer replacement, handle close, whole-session close and data-channel close cancel the old sink context; a canceled batch cannot dispatch its remaining discrete events; cancellation wakes an idle queue; a retired peer cannot wire a late channel; replacement with the same viewer ID retains the new attachment context. Expect exact identities/event sequences and `context.Canceled`, not mere callback occurrence. Mutations: substitute Background for original attachment, omit cancellation during replacement, and continue a canceled batch. Integrated CDP pressed-state cleanup belongs to the gateway/live lane.

Wave-three evidence: eight original behavioral cases failed before implementation: canceled batch continuation, blocked idle queue, already-canceled dispatch, and five actual Pion attachment/peer/channel endings. Final focused source tests collected/passed twelve tests/subtests with zero skips (2.730 seconds), followed by mutation proof. Seven faults were detected: losing original attachment context, canceling only after replacement publication, continuing a canceled batch, accepting a retired peer's late channel, omitting idle wakeup, minting per-message source contexts, and failing to notify cleanup after channel closure. The first idle-wakeup mutation survived because cancellation could precede worker startup; the test was strengthened with a context-boundary readiness handshake, then the same mutation failed for the intended blocked-worker assertion. Final restored focused command exited zero. The publication, retired-channel and stable-context checks initially passed and were proven through the corresponding faults; they are not counted as red-before-implementation cases.

Every event on a channel now receives one stable context derived from its original attachment. Peer replacement cancels it before registry publication; attachment/channel termination removes the exact current peer and notifies cleanup after cancellation. Legacy wrappers remain available. Normal peer-replacement callback semantics remain unchanged: the integration owner must release completed held-key/button records by canceled source identity before accepting a replacement source, because canceling an in-flight operation alone does not release a previously completed key-down.
