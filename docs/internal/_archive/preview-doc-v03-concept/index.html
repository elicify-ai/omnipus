The four ideas

Everything reduces to four concepts

A Workspace holds connections, agents and automations. Channels in, automations out. Context is the workspace you're in.

1 · Workspaces

The one container — My Workspace + named workspaces you create. Holds tasks, memory, calendar & connections. Context is the workspace you've selected in the sidebar switcher.

The headline shift

"Rooms"/"Spaces" collapse into Workspaces

An earlier draft generalized Rooms into three "space" tiers (User · Agent · Project) plus a global scope switcher. That's too many parallel systems doing the same job. The simpler answer: one container — the Workspace — and context is simply which workspace you've selected in the workspace switcher already in the sidebar.

The over-engineered draft (dropped)

  • Three space tiers: User · Agent · Project
  • A global scope switcher on every surface
  • Parallel keying schemes for tasks / memory / calendar
  • "Personal" as its own tier

The simplification (this doc)

  • One container: the Workspace (My Workspace + named workspaces)
  • Context is the workspace you've selected — one default, My Workspace, for the Assistant and team agents
  • The existing sidebar workspace switcher sets it — no new mode
  • Single user, one password — owner=username (#406) is just attribution, not an access gate
