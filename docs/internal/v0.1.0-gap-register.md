## Memory (Spec-5 / ADR-019)

Yardstick: the v0.1.0 foundation ships **structure + frozen logs only**; the *behaviour* layer (ranking, graph, Dreamcatcher, confidence drift, procedural authoring) is explicitly v0.2.0+. The structural foundation is implemented and faithful (two-room topology, full pinned frontmatter, the 3 re-pointed tools, bleve scorch BM25 recall, non-destructive MinHash dedup, atomic+flocked concurrency, `counters.jsonl` access logging). The **gaps all violate the spec's central "freeze the logs now → no backfill in v0.2" promise (NFR-1).**

### M1 — `op=cited` / `cited_in` events never written — **BLOCKING**
- **What:** the citation counter op is defined but never appended when an agent references a recalled memory. v0.2's citation graph + access-ranking will have **zero history** for everything created in v0.1.0 — the exact backfill the spec forbids.
- **Evidence:** `CounterOpCited` defined at `pkg/memrooms/memory_file.go:429-430`; no non-test writer anywhere.
- **Source:** Spec-5 FR-7.5, US-5 BDD ("a citation"); spec-review C-2 was closed on the promise these logs are *written*.
- **Fix:** append an `op=cited` (`cited_in`) record to `counters.jsonl` when a recalled memory is referenced in agent output. Cheap now; a backfill later.

### M2 — `born_in` provenance hardcoded empty — **BLOCKING**
- **What:** the session-provenance frontmatter field is serialized as `""` for every memory, even though the session ID is available in tool context. The v0.2 `born_in` graph edge reads this with no backfill path.
- **Evidence:** `resolveBornIn()` returns `""` at `pkg/agent/memory.go:937-939`; field present + serialized in `pkg/memrooms/memory_file.go`.
- **Source:** Spec-5 FR-7.5 / FR-7.2 ("`born_in` IS frontmatter (provenance)").
- **Fix:** plumb `ToolTranscriptSessionID` (already in ctx) into `resolveBornIn()`.

### M3 — `sessions/` firehose lives outside the room — MEDIUM (layout deviation)
- **What:** the session firehose is at `agents/<id>/sessions/` instead of the concept's `agents/<id>/.omnipus/sessions/`. Functionally fine and frozen, but not co-located in the room as the concept tree specifies; v0.2 Dreamcatcher reads the firehose from the room.
- **Evidence:** `pkg/session/daypartition.go` (day-partitioned JSONL) vs concept `memory.html:130`, `learning.html:151`.
- **Fix:** relocate the firehose into the room, **or** formally amend the concept to the current layout.

**Verdict:** structural foundation complete; frozen-log foundation ~⅔ honored. **M1 + M2 are the only items that are expensive to defer** (they'd force a backfill/migration). Close M1 and M2 before calling v0.1.0 memory done; M3 is a layout reconciliation.

## Channels — per-agent binding/routing (Spec-2 / ADR-019 FR-2)

Spec-2 is **Round-8 PASS**. The backend/contract layer is feature-complete for v0.1.0: instance-map config shape, cap-1/type (enforced at API-422 **and** config-load), `initChannels` factory map, regenerated `instance_id`/`identity`/`email` contracts, SEC-23 credential-ref routing (no plaintext), the pure-Go email channel, the full peer→guild→team→account→wildcard→default binding cascade with a **priority-0 identity override genuinely wired into the inbound loop**, the per-channel Default-agent UI control, and the new worker-exclusion (400 + FE filter). **The UI is one notch behind the concept.**

### C1 — Identity override has no UI editor — **HIGH** (UX)
- **What:** the whole `identity{acts as agent X}` axis is validated, persisted, GET-surfaced, and priority-0 routed — but there is **no editing control in the SPA**. An operator cannot set "this connection acts AS Ray" without hand-editing `config.json`. The concept frames Identity as *the* defining new axis.
- **Evidence:** validated `pkg/config/config.go:1219`; persisted `configureChannel` `pkg/gateway/rest.go:5515`; routed priority-0 `pkg/routing/route.go:95`. No `identity` control in `src/` (only generated types/zod).
- **Source:** concept `channels.html` "Identity — the new axis"; ui-changes.html Connectors row ("identity + agent binding" = v0.1.0). *(Note: strictly, Spec-2 US-8 lists only add/configure/test/enable for the UI, so this is spec-compliant but leaves the headline capability unreachable.)*
- **Fix:** add an Identity editor to `ChannelConfigPanel` (agent-vs-user selector + agent picker).

### C2 — Finer-grained bindings config-only — MEDIUM (mostly v0.3)
- **What:** peer/guild/team/account bindings work in the resolver but the UI only writes the channel-wildcard default (`account_id:"*"`). Finer bindings are `config.json`-only.
- **Evidence:** resolver `pkg/routing/route.go:102-136`; UI hardcodes wildcard at `setChannelRouting` `pkg/gateway/rest.go:5246-5251`.
- **Source:** concept "Binding — or a single conversation within it." Not in Spec-2 scope. **Largely v0.3.**

### C3 — "Connectors" rename + instance-list shape not adopted — MINOR/COSMETIC
- **What:** the screen is a fixed per-type list titled "Channels", not an instance list titled "Connectors" with an "add connection" affordance. Functionally equivalent under cap-1 (instance key == type), but not the concept's Connections shape; needs rework when the cap lifts.
- **Evidence:** `ChannelsScreen.tsx:37` (titled "Channels"); no "Connector" string in `src/`.
- **Source:** ui-changes.html "Channels → Connectors" = v0.1.0 (see G1).

**Verdict:** complete vs Spec-2's own acceptance criteria; one notch behind the concept UX. Top item: **C1 (Identity editor)**.

## Scheduler / Scheduled tasks → Automations (Spec #264 + concept `time.html` / `ui-changes.html`)

The scheduler **engine** is feature-complete for v0.1.0 (all 20 FRs of `schedules-autonomy-spec.md` trace to code): owner-pinned runs with no default fallback, per-run deadline + force-abort, session modes, semaphore-bounded lane with shutdown drain, transient-retry backoff, ask-auto-deny, capped run-history, failure notifications + channel alerts, contract-first `/api/v1/schedules` CRUD, and a card-based UI with per-agent tabs + a header notification center. The worker-owner exclusion and the #412 "Run now" fix are in and tested. **The gaps are the concept-level UI reframe + cosmetics + tz.**

### S1 — Monitor/Schedules → **Automations** reframe not built — **HIGH**
- **What:** per the concept the standalone cron **Schedules list is meant to be reframed as "Automations"** — a Trigger→Action rule builder where a schedule is just one **time-trigger** (other triggers: Event, Connection-received, Calendar; heartbeat shown via a `system` filter). This rename + rule-builder is a **v0.1.0 target and is not built** — the UI is still the cron `SchedulesList.tsx` under `monitor.tsx`. Scheduling does **not** disappear into "calendar + tasks only"; it folds into Automations and is *visualized* on the new Calendar.
- **Evidence:** no Automations route/surface in `src/routes` or `src/components` (only `CalendarScreen.tsx` references "automation"); still `monitor.tsx` + `src/components/command-center/SchedulesList.tsx`. Engine seam ready: `task_status_changed` is defined in the contract **with no producer** (a ready slot); `schedule_failed` is already a live event.
- **Source:** `time.html` ("The engine, surfaced — Automations · Trigger → Action"); `ui-changes.html` Screen 6 ("Monitor / Schedules → Automations") + roadmap row "Automations · Trigger→action rule builder · system filter = v0.1.0".
- **Fix:** build the Automations surface (trigger→action rule builder; schedules become time-triggers; `system:true` filter for heartbeat/dreaming); rename Monitor→Automations. *(Companion pieces already shipped: the Calendar shell `CalendarScreen.tsx` + route, and task `start`/`due`/`recurrence` fields in `contracts/components/schemas/BoardTask.yaml`.)*

### S2 — `scheduled` session badge missing in SPA — MINOR/COSMETIC
- **What:** backend marks scheduled runs `SessionTypeScheduled`, but `SessionPanel` renders no `scheduled` badge.
- **Source:** Spec #264 FR-017 / SC-009 (E2E asserts the badge). Close before claiming SC-009.

### S3 — Notification dropdown lacks All/Unread filter tabs — MINOR
- **What:** bell + 99+ badge + mark-all-read + click-through all present; only the All/Unread tab filter from the C-3 mock is absent.
- **Evidence:** `AppShell.tsx:107`, `NotificationPanel.tsx`.

### S4 — Timezone / DST not handled — MEDIUM (file as v0.3)
- **What:** `CronSchedule.TZ` exists but is **never read**; `computeNextRun` uses server-local time via gronx. A "9am" cron silently means server-local 9am. Not a #264 FR (the concept tags RRULE+IANA-tz as v0.3 Calendar work), but an operator footgun.
- **Evidence:** dead field `pkg/cron/service.go:109`; `TZ` absent from `contracts/components/schemas/ScheduleTrigger.yaml`.
- **Fix:** file a tracked v0.3 issue; until then document the server-local behavior.

**Verdict:** engine feature-complete. **S1 is the real v0.1.0 deliverable owed** (the Automations reframe); S2/S3 are cosmetics for spec sign-off; S4 is a v0.3 footgun to track.
