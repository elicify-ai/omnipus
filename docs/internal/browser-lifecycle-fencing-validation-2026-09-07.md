# Browser lifecycle completion fencing

Contract: a target operation begun before CloseSession or Shutdown must not recreate the removed session, attach its result to a replacement session, or report successful adoption of a discarded target. Such completion returns the sentinel `errBrowserSessionChanged` (message `browser: session changed during target operation`) and cancels its own newly created context. Existing pending creation channel identity and exact session-entry identity provide the fence; no persistent generation map is needed.

Lifecycle removal remains prompt: it invalidates pending ownership and cancels contexts instead of waiting behind the operation being stopped. Idle reaping uses nonblocking per-session command admission, skips busy sessions, and publishes any changed complete tab snapshot before releasing admission. Detached context cleanup remains outside manager locks. Existing root-owned live observers are responsible for capture-generation invalidation, including an empty tab set.

Tests use real manager methods and the existing fake Chrome creation/context boundary. Delayed first creation is interrupted separately by close and shutdown; delayed append and adoption are interrupted by close; each must return the specified error, retain no session, and cancel the created target. Reaping a busy tab set must leave it intact; reaping the active idle tab must publish the exact survivor and retain admission through its callback. Planned faults suppress pending-token invalidation, permit legacy append recreation, and bypass reaper admission/publication.

GitNexus preflight: createFirstTab LOW (3 direct/6 total, gateway startup flow); CloseSession LOW (0 indexed callers); Shutdown LOW (1 direct); ReapIdleSessions LOW (0); OpenTab LOW (0); adoptTarget LOW (2 direct/4 total). Index misses and remaining lifecycle behavior will be reported explicitly.

An existing command-gate object is retired by close/shutdown to cover the interval before an admitted command registers a pending creation token. Already-queued users of that lifetime are rejected; once they drain, the ref-counted gate disappears and a fresh request can recover normally. Tests exercise both pre-registration and queued-user boundaries, plus a replacement first creation that starts while the retired creation is still finishing. GitNexus lookups for liveTabCommandGate/acquireLiveTabCommand return absent/UNKNOWN because these are newly added lane symbols; known callers include contextual/legacy tab operations, metadata publication, and root's input/frame paths.

Explicit startup limit: ensureStarted calls pool/coordinator.Register with context.Background while releasing manager.mu. Retirement checks reject late target creation/commit, but this lane does not cancel the shared Chrome registration itself. Pool/coordinator launch ownership remains outside this finite lifecycle change and requires integrated review; no new runtime failure is claimed from this source inspection.

The implemented focused selection passed (exit 0, 28.413s), including selected existing legacy/context commands, session/creation/adoption/reconciliation, idle reaping and shutdown/close lock-safety regressions. All four deliberate faults were caught with behavioral failures: retaining a retired pending owner, ignoring retired admission, allowing the reaper through an occupied gate, and suppressing reaper publication. Source was restored after every fault. The final restored race/shuffle selection passed (exit 0, 38.741s). Full CI and integrated live capture/UI verification remain parent-owned and are not claimed here.
