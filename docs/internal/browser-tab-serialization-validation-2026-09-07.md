# Shared browser target serialization

Contract: UI input and viewport work must not overlap a target mutation from legacy tools, session recovery, popup adoption, or reconciliation. All such mutations use the same per-tab-set command gate, including the synchronous observer publication. Waiting never holds the manager mutex. Target listeners remain nonblocking and coalesce pending metadata publication; after acquiring the gate, publication reads the current snapshot rather than replaying an older event snapshot.

Tests use the real manager with fake Chrome transport/context creation at the existing process boundary. Cases hold the real command gate and invoke each public mutation path, asserting no completion or model publication until release. A canceled contextual switch waiting behind legacy work must leave the active index unchanged. A burst of target metadata while the gate is occupied must publish one final complete snapshot after release. A live tab callback for a missing or dead target must never invoke creation. Positive snapshot results retain the exact context and target identity; missing and dead contexts produce actionable errors.

The independent oracle is the approved shared-gate ordering contract, not observed implementation output. Planned mutations remove legacy admission, release the gate before callback completion, and publish captured event state without gated re-snapshotting. Known boundary: manager shutdown and idle reaping require explicit lifecycle review; this lane must report their treatment, not imply that three tab-button methods alone establish complete safety.

Legacy gate admission uses the configured page timeout, while existing creation/foreground operation budgets retain their established semantics. Reconciliation serializes its read/list phase, releases admission, then serializes each adoption independently. This is not a whole-pass transaction: holding the gate while waiting for an already-registered popup adoption would deadlock if that adoption itself awaited the gate. Concurrent callers for the same target retain the existing shared adoption outcome.

GitNexus preflight reports Session LOW (2 direct/5 total, gateway startup flow), OpenTab/CloseTab/SwitchTab LOW (0 indexed callers), adoptTarget LOW (2 direct/4 total), handleTargetEvent LOW (1 direct/7 total), ReconcileTabs LOW (0 indexed callers), onTabsChanged LOW (1 direct), and BrowserManager LOW (1 direct). notifyTabsChanged is MEDIUM (6 direct/14 total); changing gate ownership through its callbacks therefore requires the explicit non-creating live callback lookup.

## Observed verification

Initial focused run failed for the intended behaviors (exit 1, 7.643s): all six legacy admission cases completed through an occupied gate; metadata published before admission; missing/dead live callbacks attempted creation; a contextual switch crossed an unfinished legacy callback; the read-only API stub rejected a live target; and configured admission expiration was ignored. The missing-target negative guard already passed the stub.

Implemented selection passed (exit 0, 40.189s), covering the new cases and existing contextual commands, session/open/close/switch/adoption/reconcile, callback lock-safety and target-event tests. Three deliberate faults were caught with behavioral failures: bypass Session admission, release SwitchTab admission before its observer completes, and bypass metadata admission. All source was restored; the final race/shuffle selection passed (exit 0, 45.236s), also including the existing live tab-change recapture test.

The existing fake live recapture bridge was updated to the same read-only resolver as production, retaining its exact recapture assertions; its impact preflight was LOW with no indexed callers. The existing gate helper's explanatory comment changed only; its impact lookup returned absent/UNKNOWN because the root index predates that new helper, and its implementation remains unchanged.

Remaining required follow-up: CloseSession/Shutdown/idle reaping still remove sessions outside admission. Legacy creation/adoption must reject a completion belonging to an old exact session entry or invalidated pending-creation token; legacy OpenTab currently recreates on a missing-session completion. Idle reaping can change active target without publishing the transition. Those lifecycle paths are deliberately not reported as fixed by this commit. Full CI and integrated runtime verification remain parent-owned.
