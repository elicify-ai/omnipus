# Omnipus 0.1.0 — Build Plan & Execution Kit

**Source of truth for decisions:** `remediation-decisions.md` (Part 0 = IN/DEFERRED scope; the decision log IS the spec of record — no separate ADR).
**Concept:** `.preview-doc/*.html` (updated 2026-06-21 to match decisions).

This is a **production** completion effort on the existing app — no prototype, no mock data, no throwaway MVP.
Most of 0.1.0's foundation is already built (M1–M12 sweep): the work is **consolidation + the
workspace-as-project IA reframe + targeted additions**, all landed production-ready in the real `src/` and `pkg/`.

## Strategy
Contracts-first (Constraint #8): the data-model spine is authored in `contracts/` and regenerated **before**
any Go/TS code, because every downstream sprint (BE stores, FE views, delegation) binds to those wire types.
The IA reframe (workspace-as-project) is the long pole and highest-value surface — designed and built well
against the real Sovereign Deep design system, not sketched.

## Execution method
Each sprint runs the wave pattern: fan out parallel dev agents (frontend-lead / backend-lead / security-lead /
qa-lead) → 7-reviewer quality gate → fix wave → CI on the ci-omnipus worker (never the full suite locally;
tags `goolm,stdjson`). Contracts-first. No merge to `main` without human review.

## Artifacts subagents need (this kit produces them)
1. **This build plan** (sequence + dependencies).
2. **`remediation-decisions.md`** — the locked decisions (spec of record).
3. **Per-sprint specs** — produced as each sprint starts; Sprint 1 = the contract schema diffs first.
