# Grill-Spec Review — Live-Browser Video Streaming (WebCodecs relay), **Revision R2 (A2 pivot)**

- **Spec reviewed:** `docs/internal/specs/live-browser-video-streaming-spec.md` (R2, post A2 pivot)
- **Source ADR:** `docs/internal/architecture/ADR-044-live-browser-video-streaming.md` (§6.0 A2 amendment) + `ADR-044-spike-results.md`
- **Prior review:** `docs/internal/specs/live-browser-video-streaming-spec-review.md` (R1). This round2 file is written alongside it to preserve history (project `-review-round2.md` convention); it does **not** overwrite the R1 review.
- **Mode:** `plan-spec` (BDD + FR/SC + traceability present)
- **Reviewer stance:** adversarial, read-only. This pass verifies (a) the A2 pivot's new claims are feasible/secure, and (b) that R1-review findings still in force (C-1..M-9) are genuinely closed in R2 — not just re-asserted.

---

## Executive Summary

The A2 pivot is honest about *why* it exists (capture needs a framebuffer) and the R2 spec adds real structure the pivot demanded (Xvfb/PulseAudio sidecar user stories, decoupled audio, corrected H.264-main codec policy, loopback RemoteAddr enforcement, a fps gate). But three things make it a BLOCK. First, **the entire heavyweight A2 stack is committed and built *before* the one measurement that justifies it** — the integrated capture fps (Test 23/SC-003) was never measured (sandbox-blocked), the spike author's own recommendation was the *lighter* A1 path, and the gate is positioned after the installer-default flip and the all-browsing-goes-headful switch, not before. Second, **the load-bearing security control — isolating capture so agent-browsed pages can't capture despite a process-global auto-accept flag — may be architecturally infeasible as written** and is deferred to `/taskify` with no proof. Third, **the CDP-port token-confidentiality gap R1 called critical is re-asserted as a requirement but its mechanism is again deferred**, and the code confirms a fixed debug port. Layered on top: A1 (the spike-proven lightweight path) is silently abandoned as the degradation tier, non-Linux platform coverage is undefined, the primary-device (iPad) decode gate was never run, and several R1-review MAJORs (fragment wire fields, ingest reconnect, viewer-authz test, observability test, escape hatch) are carried forward unresolved.

**Findings:** 3 CRITICAL, 11 MAJOR, 5 MINOR, 4 OBSERVATION.

**Verdict: BLOCK** (3 CRITICAL findings).

## Test Coverage Assessment

- **Strong:** ingest auth matrix (DS-4, Tests 1–2), codec/single-encode matrix (DS-1, Test 9), per-viewer backpressure + aggregate LRU (DS-3, Tests 5–6), fragmentation reassembly *bound* + timeout (FR-014 — the R1 C-1 DoS is now bounded and counted in the budget: a genuine improvement).
- **Elevated gate (good):** Test 23 (integrated CI fps) is correctly promoted to a hard go/no-go — but it is sequenced *after* the architecture is committed (C-1).
- **Gaps:** viewer-attach authz before GOP replay (M-6); metrics emission (M-7); ingest-leg reconnect (M-5); the capture-**isolation mechanism** that Tests 3/14 assert but nothing specifies how to make pass (C-2); the CDP-token-unrecoverable test named in FR-013 prose but absent from the table (C-3); audit trail (m-2); the fragment path is untestable until the wire fields exist (M-4); audio daemon-restart-mid-Chrome (M-11).
- **Concurrency/DoS:** reassembly and GOP memory are now bounded; **per-viewer send-queue memory under many viewers is still unbudgeted** (M-9).

## Unasked Questions

1. If Test 23 returns < 24 fps on `ci-omnipus`, is the entire A2 stack reverted — and to A1 or to nothing? Why is the fps gate scheduled *after* the installer-default flip and the headful switch rather than before? (C-1)
2. In a single headful Chrome with a process-global media auto-accept flag, what concretely denies an agent-browsed page's `getDisplayMedia`, and has it been *demonstrated* rather than asserted? (C-2)
3. What gates the fixed CDP debug port so a co-tenant (or agent-browsed content) can't read the ingest token from `/json` before it's consumed? (C-3)
4. Why does a no-Xvfb / macOS / Windows / Termux install get "unavailable" instead of the spike-proven A1 (headless CDP→WebCodecs) experience? (M-1, M-3)
5. Does the operator's iPad actually decode H.264-**main** (not baseline)? S-2 was never run; if it and VP8 both fail, is "unavailable on the primary device" an acceptable ship state given it started this ADR? (M-2)
6. Where are the fragment fields in the ingest envelope that Test 13 parses? Why fragment at all instead of sizing the ingest bound to the max keyframe? (M-4)
7. Does a transient ingest-WS drop permanently kill the stream under the single-use token? (M-5)
8. Can Chrome pick up a restarted PulseAudio's `PULSE_SERVER` without relaunch (US-11/AC-3), and was it tested? Does the Chrome launch block on PulseAudio readiness or not? (M-11)
9. With JPEG removed as a live tier and the kill-switch producing "unavailable," what is the operator's runtime escape hatch when video regresses in production? (M-10)
10. Show the arithmetic: GOP ceiling + Σ per-viewer send queues + reassembly buffer < 10 MB for the worst supported (streams × viewers). If it doesn't fit, what is the real Go budget, and what is the documented total-footprint / min-spec? (M-9)

## Verdict

**BLOCK** — 3 CRITICAL (C-1 the fps-gate is sequenced after the architecture it justifies; C-2 capture isolation may be infeasible under a process-global auto-accept flag; C-3 CDP-port token confidentiality re-asserted but unclosed), plus 11 MAJOR (A1 abandoned as fallback, iPad decode gate un-run, non-Linux coverage undefined, fragment wire fields missing, ingest reconnect, viewer-authz + observability untested, equivalence bar unmeasurable, footprint/min-spec ungated, no escape hatch, audio-restart feasibility).

Note: C-1, C-2, C-3, M-1, M-2, M-3, and M-10 touch ADR-044's A2 amendment (§6.0/§6.3/§6.6) and the spike's own A1 recommendation — the revision should reconcile the ADR in the same pass, not just the spec. In particular, whether A1 becomes the degradation tier and whether the fps/capture-isolation gates precede the installer flip are ADR-level calls.
