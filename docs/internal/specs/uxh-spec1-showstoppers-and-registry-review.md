# Grill-Spec Review — Spec-1 (Showstoppers + Tool-Registry Metadata Correction)

**Reviewed:** `docs/internal/specs/uxh-spec1-showstoppers-and-registry.md`
**Date:** 2026-06-03 · **Mode:** plan-spec (full structural checks)
**Reviewer disposition:** adversarial, read-only. Verified every code claim against the live tree on branch `epic/uxh-wave0ac`.

---

## Executive Summary

22 findings: **4 CRITICAL, 9 MAJOR, 6 MINOR, 3 OBSERVATION**. Many code-line claims in the spec are accurate (the `gateway.go:689` deps-drop is real; `appliedConfig` is genuinely set once at boot; providers status is hard-coded `Connected`; font-size CSS var is unconsumed). But the spec's central correction — surface general-builtin metadata so the editor is non-empty — collides with **undifferentiated category data** (`exec`/`read_file`/`web_search` all report `category:"core"`, which has no FE label), so the "fixed" editor renders one giant raw-keyed `core` bucket. Three more blockers: the D-B2 re-baseline introduces an **unsynchronized concurrent write** to a field documented "never mutated after boot" (a `-race` failure waiting to happen); the wave plan's "disjoint file ownership" claim is **false** (`gateway.go` is edited by two parallel teams); and the editor "flatten" prescription is underspecified against a 5-section component that two call-sites depend on.

**Verdict: BLOCK.**
