## 1. Executive summary

The three specs agree on the two artefacts they were most careful about — `Provider.status` (six values, byte-identical in S67 FR-024 and S68 FR-038) and `EntitlementResponse.yaml` (same shape in S67 A-13 and S68 Data Constraints) — and on `ContextSettings.yaml`, which only S66 defines and S67 references consistently. Beyond those two, the seams are not closed.

Two findings block on their own. **(X-01)** Every new `LLMError` code lands in a contract that physically exists in **four** hand-kept copies (`LLMError.yaml`, `LLMErrorReplay.yaml`, and the inline `LLMError` / `LLMErrorReplay` blocks in `asyncapi.yaml`) guarded by `TestContract_LLMError_AllClassifierCodesRoundTrip`; S66 names one file, S68 names a different one, and neither names the replay copies — so whichever spec lands second ships a drift failure or a silent half-edit. **(X-02)** The `needs_provider` error code that S67 refuses turns with, and that S68's precedence rule and SC-013 are built on, is not in any contract list; the `LLMError` enum is closed and codegen hard-fails on a code without copy and attribution, so the behaviour both specs depend on cannot be generated as written.

The rest of the MAJOR set falls into three groups: **(a)** symbols that one spec deletes and another still builds on (`claude-cli` kept as an exempt provider by S66 while S68 deletes it and adds a CI gate that S66's own test literal and spec file would fail; `knownProtocols`/`IsKnownProtocol` deleted by S67 and asserted by S68's test 4; the factory "classification table" and "new `lmstudio` id" S66 adds to a switch S67 removes); **(b)** shared fields specified differently or by nobody (the entitlement cache key — `SHA-256(key)` in S67, `hash(credential ref)` in S68; the `ProbeProviderRequest` shape — `protocol` in S67, `auth`/`api_key`/`model` in S68, custom-endpoint rows that disagree; how a custom row is recognised once its id is operator-chosen; how a `cli` protocol row picks between two (three, with Copilot) constructors; who computes the window the default-model card shows; what wire state the "endpoint reported no context length" refusal takes); and **(c)** one genuine ADR-level design contradiction — A66's cloud live-limits rung (24 h TTL, background refresh at instance build) versus A67's "live calls remain for exactly three things" and S67's prohibition on `/models` "on a timer or at boot".

Sequencing is not "three parallel builds". S67 must land first and must carry the **whole** coordinated `Provider.yaml` / `Agent.yaml` / `ProbeProviderRequest.yaml` edit (its own T31b already asserts S68's values); S68 follows; S66's backend (D4–D7, D10) can be built in parallel but cannot merge before S67 (it needs `catalog.Resolve(provider, model).Window()` and a `protocol`-based exemption rule), and its provider-row/picker states need S68's surfaces. The dependency graph is in §4.
