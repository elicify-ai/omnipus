# Spec-3 Review — Agent Roster Re-cast, Delegation Policy, Orchestrator & Max-Parallel

- **Spec under review:** `docs/internal/specs/v01-spec3-agents-delegation-orchestrator-spec.md`
- **Mode:** plan-spec (FR/SC/BDD/Traceability present)
- **Reviewer stance:** adversarial, read-only, grounded against the live tree (`pkg/coreagent`, `pkg/agent`, `pkg/config`, `pkg/routing`, `pkg/api/generated`, `src/`).
- **Date:** 2026-06-13

## Executive Summary

This spec ships clean prose but is built on several **factually wrong groundings** of the live tree, and it explicitly defers the most load-bearing grounding ("the exact as-is delegation policy struct is grounded at impl") that — once actually grounded — invalidates two of its central claims. The "2 ungated work paths" framing is wrong (one path is gated by `Subagents.AllowAgents`, a second by `CanDelegateTo`; only the sync `subagent` tool is truly ungated). The orchestrator's trigger event (`task_status_changed`) **has no server-side emitter anywhere in the codebase** — it is a generated WS frame with zero producers, so the coordinator has nothing to subscribe to. The "voice already exists" lesson is false: the existing `VoiceConfig` is a **global** STT/TTS engine config, not an agent-scoped persona field; `voice` on a persona is a brand-new field. The compiler-oracle claim for the Max retirement is materially false — most breakage is in **string-literal and role-name test assertions** the compiler cannot see.

**Findings:** 4 CRITICAL · 7 MAJOR · 4 MINOR · 2 OBSERVATION.

**Verdict: BLOCK.**

## Test Coverage Assessment

- **Negative tests:** present for delegation deny (#3) and gating (#5), but #5 targets the wrong paths (C-1).
- **Concurrency:** #7 is `-race`, good — but only covers the inbound-session path AdmissionController actually gates (M-4), not subagent/task fan-out.
- **Idempotency:** `SeedConfig` is idempotent today; no test asserts the **re-seed** of a config that already has the *old* 5 agents collapses correctly to 4 (the orphaned-`max` case, M-7).

- **Contract test:** #9 (`verify-contracts`) is correct and necessary given the new `voice`/policy schema.

## Verdict: **BLOCK**

Four CRITICAL findings (C-1 mis-located work paths, C-2 unreconciled triple allowlist, C-3 non-existent orchestrator trigger, C-4 false "voice exists") each independently rest on a wrong grounding of the live tree, and the spec's stated mitigation for all of them is "ground at impl" — which is precisely where this spec needed to do the grounding. Address the CRITICAL and MAJOR findings (especially the three real as-is allowlists, the real status-change hook, and the new `voice`/`max parallel` fields) before re-grilling.
