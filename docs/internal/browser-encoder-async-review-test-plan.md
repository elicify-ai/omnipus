# Encoder asynchronous lifetime review

A shutdown that wins before a target lookup finishes must prevent new capture and unmute side effects. If shutdown wins while Chrome is already processing an unmute, the exact tab must be muted again after that operation settles; no stream or offer may then be published.

Adaptation work belongs to its original peer, local capture attempt and adaptation reset. A late stats result or sender-parameter completion must not change the replacement state, report a failure against the replacement, or publish stale diagnostics. Only one adaptation tick may be outstanding; overlapping timer ticks are dropped. A queued parameter update must revalidate before touching its sender.

Tests execute the actual embedded module in the existing Node VM harness, replacing only Chrome/media/peer APIs. Controlled promises force lookup, unmute, stats, queued parameters and parameter-completion boundaries. Independent expected outcomes are no late capture, final local mute, preserved explicitly reset state, no stale sender writes/error reports, and one outstanding stats request. Existing actual recapture-handler tests remain; the disconnected historical skip-policy harness is removed with its dead policy. Minimum mutations will remove the shutdown compensation and adaptation lifetime fence after initial red/green proof.

## Results

The Node red run reproduced all three logical failures: capture continued after a shutdown during target lookup; old stats changed replacement adaptation state; overlapping ticks performed another decision. After correction, both shutdown schedules, six retired adaptation schedules (peer, capture attempt, reset, parameter success/failure and queued write), and overlap handling passed. A fixture originally used Chrome's empty pre-negotiation encoding placeholder; it was corrected to a negotiated active encoding before interpreting sender-write assertions.

Two deliberate faults were caught and restored: removing the compensating mute made the late unmute leave the tab audible; bypassing the adaptation lifetime fence allowed old stats to change replacement state. The restored Node run passed all three tests. The focused Go selection passed twelve existing/new top-level cases, including the twenty-case adaptation harness and the version/hash gate. Its one coalesced-capture expectation still required the canceled old capture to acquire media; that assertion was tightened to require replacement-only target, geometry and live track, and its isolated rerun passed (1.183 seconds). Thirteen relevant top-level cases are therefore covered with zero skips. No full suite or race detector run was added for these JavaScript promise-order changes.

The removed skip-policy harness was disconnected from the actual recapture handler and contradicted explicit recovery semantics. Its historical1.0.17 content hash was retained in the central version map. Actual handler recovery, coalescing, immutable geometry and connected-peer preservation tests remain. Extension version1.0.20 and its matching asset hash ensure existing installations reseed the corrected encoder.

GitNexus impacts were LOW for changed capture/adaptation functions and the removed policy/test (zero indexed affected processes; the largest result was the adaptation-stop helper with two direct callers/eight total). Version/reset/init names were ambiguous in the stale index; their current extension-local callers and the hash/seed contract were manually checked. New test symbols were absent from the index and manually scoped to the embedded-module harness. Final staged scope is checked before the commit.
