## Context

Mia needs one reliable main conversation in each workspace. Clicking her opens it; **+ New chat** on her row deliberately opens an extra chat. A heartbeat uses the main. A task assigned to her normally runs as its real child, but the task still owns its goal, run and result. Asking `@Jim` requests Jim's answer; it does not replace Mia. This is a change to existing paths, not another coordinator or chat product (founder record; specification FR-002/017/026/029).

**Delegation context, 2026-10-09:** the founder rejects both an implicit target and the hardcoded Jim/General Purpose self exception. People must see/edit/remove the self permission in the existing workspace policy editor; an agent in its main or extra chat names itself and forks a distinct child. The source baseline already has the ordinary launcher and workspace store, but its validators/runtime/seed/UI still restrict self by identity. Reuse those owners; config seed defaults replace the exception without granting membership or tools. Judge and plans coordinator remain explicit no-self-default seed records; Planner is not excluded. Authority is the delegation amendment header; specification FR-014/015, C-DELEGATE and E-DELEGATE-CONFIG, E-DELEGATE-CREATE and E-DELEGATE-EDITOR.

**WC-1 context, 2026-10-09:** the founder settles the distinction between starting an extra chat and clearing the current chat. `/new` is retired; local **New chat** creates an extra. `/clear` instead clears the current display and model context by advancing the context window, preserving the transcript and starting no session. This is one semantic contract for the SPA, backend and channels, consistent with Q-R2-9; it supersedes any earlier ambiguity about whether `/clear` deletes history. ## Decision

### D1 — One main per eligible workspace/agent pair

Mature the existing standing-session path into `main-session-<workspace-id>+<agent-id>`. **Correction, 2026-10-08 (final F1/F2, founder Q1=B):** `+` cannot occur in either validated ID alphabet, unlike the old hyphen join. `a-b`/`c` and `a`/`b-c` now yield distinct IDs `main-session-a-b+c` and `main-session-a+b-c`. Keep workspace/agent bounds at 128; cap the **computed ID at 255 UTF-8 bytes**. Above that, visibly refuse before creation/attach/dispatch and explain the 255-byte limit; no hash, truncation, alias or second short ID. Exactly 255 is valid. Validate the persisted pair and immutable `agent_id`, not just an ID match. Eligible native chat-target agents have one main per membership; workers and other hidden system agents have none. **Admin has one main in the default workspace only**, is displayed like a main colleague and is messageable/@-addressable there. His standalone/no-team operator role, fixed tools and self-helper restrictions otherwise remain (FR-002/045; C-MAIN; `pkg/gateway/rest_workspaces.go::validWorkspaceID`; `pkg/agentstore/state.go::ValidateAgentID`).

Pin/protect main independently of heartbeat enabled. Heartbeat runs in it; Stop, idle and revival do not mint another main. Membership removal immediately hides it from UI/channel/task addressing and admits no new work through that membership. Already-authorized runs settle and keep outcomes without waking the hidden main; re-add reveals the retained pair until normal retention (original Q5=A; FR-003/007).

Contract names remain **Session.type = main**, required current-format type; immutable **Session.agent_id** and the **existing optional Session.workspace_id**; computed **Session.protected** and read-only **WorkspaceMemberConfig.main_session_id**. **Do not add workspace_id to Session.yaml's required list**: it applies to all sessions, including legal ones with no workspace. Set it on a main, enforce required/nonempty when type=main in the server, and state the condition in the field description; no second workspace field. Delete stored **heartbeat.session_id** and mutable handover **active_agent_id**. Main is server-created, not in client-create enums. Backend-lead widens **session_id maxLength 128→255 on every own-session-ID round-trip carrier** (about 30 bounded fields plus inline mirrors, and bounded main/parent/recipient ID carriers as applicable) and regenerates before consumers; workspace_id/agent_id stay 128. Existing unbounded Session.id must round-trip the same computed ID. Expose Admin through existing Session list/detail, not fake team membership (C-MAIN; final F2/F6; DEL-01/07, DEL-F07/09–13).

### D2 — One append-only archive, two views and a bounded model window

Use one content entry format for chat/model/both, UTC day files, and a `(file, byte position)` model-start mark. Append and model steps read the required bounded window, not lifetime history. Acceptance order governs append order even when source timestamps are delayed. Midnight does not split a conversation or invalidate tool-call/result groups; full result references and session-scoped recall remain (FR-004–006; E-STORE).

Clear, interrupted-turn corrections and view changes append effects or move metadata; they never rewrite prior retained bytes. **Clarification, 2026-10-09 (WC-1):** `/clear` uses this existing window-move mechanism to clear the chat display and model context, not retained transcript content. “Compaction” here means advancing the context window, not deleting history, starting a session or adding a summary writer (D8; FR-006/030; C-CONTROL; BDD-09.2). No new compaction-summary writer: idle recap writes agent memory. A supported compaction entry tag does not imply a writer. Existing whole-tool/turn protections and provider-valid replay remain (Q-R2-8; FR-006/036).

Keep `retention.session_days`, default 90 days by file modification age, including disabled retention. Old main content expires despite identity protection. If the marked day expires, advance to the first retained complete message/tool group and tell the agent older history expired; if nothing remains, use an empty window under the same ID (original Q2=A; FR-007; DEL-09–12).

#### CONV — Same saved chat, one current store

Backend-lead implements the bounded unit in specification::CONV, grounded by E-CONV. Convert existing saved shared/per-agent session data and currently supported saved JSON/JSONL sources only; keep original session IDs, **agent_id as owner**, existing optional workspace_id, titles/timestamps/task/parent/connector/upload references and guest authors. Persist missing type once as chat, preserve valid non-heartbeat type, drop active_agent_id without handover. Existing saved chats are **not promoted to computed mains**; do not infer a workspace or owner, make an alias or restart old work. The current-format one archive preserves full chat/model/tool content, ordered identities, window/projection/recall and retention age (FR-004–008/038; final F3).

C1a/U1 supply current identity/contract shape and U2 supplies the canonical archive writer. CONV runs at first cutover boot **before** current cache/list/attach, retention or task/scheduler/agent dispatch. Build/verify current same-ID content/window/references, publish current metadata atomically using existing file locks/writes, then retire the old source; never delete the only readable copy first. A nonempty/existing destination alone is not completion proof; conflicting identity/content is visible refusal, not overwrite. Interrupted publication/cleanup retries once-per-chat idempotently at next boot without duplicate messages; failed cutover retains recoverable source and does not open partial ordinary serving/dispatch. Fresh/current install is a no-op. No second live store, conversion service/ledger or address map (specification::CONV / BDD-12.6 / T35).

DEL-09/10/11 remove the generic importer helpers, per-agent/SessionManager fallback scans and PostLoad/missing-type normalization **from runtime** in the same assembled cutover after CONV exists. This supersedes the earlier CONV heartbeat conversion in PLAN::13/14, not the requirement to keep saved chats (FR-038; founder narrowed Q2).
