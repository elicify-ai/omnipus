## Context — what forced this redesign

### The benchmark observation (operator, verbatim intent)

> "the benchmark is claude code where I can set a goal without any delay it is just happening instantly — why is it so different"

Claude Code has no goal machine: the task IS the prompt, work starts in ~1s, structure (todo list) is a **tool the working model calls mid-flight**, questions happen mid-work, verification comes after. Omnipus v0.1.1 instead built a **contract-negotiation gate in front of work**: compile LLM call → clarify questions → second compile LLM call → human confirm → only then round 1.

## Decisions

### D1 — INSTANT ACTIVATION: `/goal <intent>` activates the goal and starts work in the same turn; the pending/confirm state is deleted

`/goal <intent>` (prose/LLM path):

- The goal record is created **active** immediately: `GoalID` minted, `GoalCondition = intent`, `GoalRoundsUsed = 0`, `GoalStartedAt = now` — the same fields `confirmPendingGoal` writes today, written up front. `PlanEngine.Admit("goal")` runs once, before activation (`[grill-verified]` Admit is side-effect-free and recomputes from persisted state, so the collapse from two Admits to one double-counts nothing).
- The turn **continues into round 1 with the raw intent as the working prompt** — the same `opts.UserMessage`-rewrite mechanism the fresh-activation branch of `applyGoalCommandPrompt` uses today, applied at `/goal` time.
- `GoalCriteriaJSON` starts EMPTY and is filled by the agent via D2. *Active goal + empty record* is a legal, expected, transient state — it is also D3's forcing predicate and D6c's nudge predicate, bounded by both.
- **Marker-only path `[G-m13]`:** a `/goal <markers>` on a session with NO active goal stays exactly as today (deterministic compile, immediate activation, zero LLM calls). A restate — `/goal <anything>` while a goal IS active — no longer produces a pending amendment awaiting confirm (`proposeGoalAmendment` dies): a **marker-only restate** applies immediately — deterministic `compileGoalIntent`, its feasibility veto retained as-is, result written to the record as an update, diff logged (D8) and rendered (D5); a **prose restate** rewrites the turn's working prompt (same mechanism as activation) and the agent updates the record via `set_goal(mode: update)`. Steering philosophy either way: no confirm ritual.
- **Deleted:** the pending-confirm state, bare-confirm interception, `/goal confirm` as an activation verb, the `queued` pill emission, the Confirm/Amend/Cancel row (D5/D9). **`/goal confirm` recognizer (spec-grill B3 correction):** `isGoalConfirmVerb` dies with the rest; the informative no-op reply ("goals activate immediately now — just state your goal") is implemented as a NEW inline verb match in the command router — without it, `/goal confirm` would fall through to the prose path and activate a goal literally named "confirm". Bare "confirm" chat text is intercepted by nothing and passes through as ordinary chat.

### D2 — SET_GOAL: a thin, validated write-path tool over the EXISTING goal record; no new structure

A new builtin tool `set_goal` (normal two-layer tool policy per ADR-077; shipped default `allow` in `pkg/config/defaults.go` + per-agent seeds like every builtin):

- **Args mirror the existing compiled-goal record exactly**: `definition` (required), `criteria[]` ({text, judgment}, ≥1), `dod[]` ({text, judgment, provenance}), `assessment` ({clarity, assumptions[]}), `mode: register|update`.
- **Every deterministic guard the compile applies today applies on the way in**: `NormalizeCriteria`, `validateCriterion`, `IsValidJudgment`, the DoD floor (`newFloorDoD`, ≥1 guaranteed), feasibility vetting. A failing submission is rejected back as a tool error (bounded retry loop) — the guarantee lives in code.
- **Scope preconditions `[G-M9]`:** the tool refuses (tool error, no write) unless (a) the calling turn's OWN transcript session carries an active goal (`GoalCondition != ""`), and (b) `ToolDelegationDepth(ctx) == 0` — mirroring `ask_user_question.go`'s `:180` depth gate. A delegated sub-turn or goalless session can never mint an orphan record. (Belt-and-suspenders: `goalIdleExpirySweep`'s skip predicate gains `GoalCriteriaJSON` so any historic orphan is sweepable.)
- **Write target is the same store field** (`GoalCriteriaJSON` via `session.MetaPatch`) the compile writes today; judge (`compiledGoalCriteriaFor` = criteria ∪ DoD), keeper, `/goal status`, SPA all keep reading what they read now.
- **`mode: update` (steering)** applies the same validation, then computes the change summary via `diffGoalAmendment` against the current record `[G-M5]` — that differ's ONE surviving caller is this handler — returning the diff in the tool result and logging it (D8).
- `assessment` (clarity + assumptions) is a tool ARG that is validated and **logged via D8's register event — NOT persisted into the record** (round-2 B-2: persisting it would change the `CompiledGoal` shape this ADR everywhere declares unchanged, rippling into `loadCompiledGoal`, the judge feed, and the pre-upgrade path). "Why did it proceed instead of asking" stays answerable — from the log.
- **Zero contract/wire changes**: tool parameter schemas are `Parameters()` maps, not `contracts/` schemas; the `goal_status` frame schema is untouched (`[G-M10]` — the SPA render path is D5's typed-frame emission, never a hand-parsed tool-args shape, so Constraint #8 is not grazed).

### D3 — TWO-DOOR FORCED FIRST MOVE: determinism from request shape, not prompt hope

The workflow lives in the engine; the model authors content. The **forcing predicate is pure session state** `[G-M7]`: *active goal AND empty `GoalCriteriaJSON`* — evaluated on ANY turn's first LLM request for that session (activation turn, the resume turn after a clarify card, a D6c nudge turn), independent of how the turn originated (`UserInitiated` or not — an auto-submitted card resume is still a goal turn). No correlation record is needed; the goal-side `goalClarificationRecord` and its writer die (D9).

- **Layer 1 — forced choice of exactly two tools (webchat origins).** When the predicate holds and the session's origin channel is webchat, the engine narrows the request's tool surface to **{`set_goal`, `AskUserQuestion`}** and sets provider tool-choice to *required*. Confident → `set_goal` (turn continues into free work, full surface restored next request). Not confident → `AskUserQuestion` — the existing card; the turn parks (`TurnEndStatusParked`, the tool's own park machinery); the answers arrive as a resume turn where the predicate still holds and the pair is forced again. **Question-round budget:** one question round per goal **generation (per `GoalID`)** — and a restate (prose or marker) **MUST NOT mint a new `GoalID`** (round-2 M-7: only a fresh activation on a goalless session mints; a restate that re-minted would silently reset the budget) — tracked on the goal record (`GoalQuestionRoundsUsed`, new meta field — greenfield, no compat concern); once spent, the narrowed surface is `{set_goal}` alone.
- **Layer 1 is a BUILD, not a flip `[G-B1]`.** Nothing in this repo can carry a tool choice today — the only `tool_choice` occurrences are hardcoded `"auto"` (`pkg/providers/openai_compat/provider.go::buildRequestBody` `:112`; `pkg/providers/azure/provider.go::Chat` `:116`). Required work: a typed `ToolChoice` field in `pkg/providers/protocoltypes/types.go` (typed, NOT an untyped `options` map key — a typo must fail compile, not degrade to auto), honored by ALL native request builders: `openai_compat`, `azure`, `anthropic`, `anthropic_messages`, `bedrock`, `codex_provider`. Two traps, stated: (a) `openai_compat` merges per-provider `extraBody` LAST — the forced tool-choice must be applied after that merge (or the merge must not override it), else an operator's `extra_body.tool_choice` silently defeats the forcing with no error; (b) the CLI providers (`codex_cli`, `copilot_cli`) flatten tools into a text prompt — Layer 1 is structurally inapplicable there; those turns run Layers 2–3 only.
- **Surface-narrowing mechanics `[G-m11]`:** the narrowed pair is the **intersection** with `FilterToolsByPolicy`'s output — never a substitution; if policy denies `set_goal` for this agent, no forcing happens (Layers 2–3 only, WARN logged), because forcing a tool the exec gate denies is a guaranteed error loop. Compressed-mode `ToolSearch` force-through is **suspended** for the one narrowed request ("exactly two" is exact). The `gracefulTerminal` branch (which nils the tool defs) also clears tool-choice — `required` with no tools is a provider 400.
- **Non-webchat origins `[G-B2]`:** `AskUserQuestion` is **permanently web-only** by operator ruling (`pkg/tools/ask_user_question.go` `:186` hard-errors on any non-web channel; it also refuses at delegation depth and under auto-deny). The old "plain-chat clarify fallback" was a property of the deleted compile coupling, not of the tool. So on channel origins (Telegram/Discord/…) and on keeper-delivered turns (`Channel: "system"`): **no Layer-1 forcing.** The first request offers the normal surface plus `set_goal`, and the injected rubric (D4) instructs: register when confident; when not, ask your question **conversationally** and register after the reply (the next user message IS the answer — steering). The invariant never rested on Layer 1 (Layers 2–3 hold everywhere); Layer 1 is the webchat happy-path accelerator.
- **Layer 2 — validation with bounded retry** (D2's guards; the standard tool-error loop).
- **Layer 3 — keeper backstop** (D6c) + **engine fallback compile** (D7): if a model never walks through a door, code does.

### D4 — RUBRIC RELOCATION: the compile's contract becomes a per-turn engine injection; the front-path compile call and clarity-gate call are deleted

- The clarity rubric (ask vs proceed), the checklist-authoring guidance (judgment types, the 4-layer DoD derivation ladder), and the `define-goal` skill content move from `compileGoalIntentLLM`'s request into a **turn-scoped system note** injected by the engine whenever D3's predicate holds (activation, clarify-resume, nudge turns). NOT the global soul prompt — deterministic, code-owned, per-turn.
- **Assembly reuse, minus one feed `[G-M6]`:** the injection builder = compile-contract text + `loadDefineGoalSkillContent` ONLY. Workspace/project instructions are **already injected on every turn** (`pkg/agent/loop.go` `:9346` `injectWorkspaceInstructions(...)`); re-including them from `buildGoalCompileMessages`' assembly would double-inject. The 20k-token session-window feed (`goalCompileWindowText`) is also NOT injected — the turn carries the session window natively. The new note **registers in `pkg/agent/midturn_budget.go`'s per-turn note enumeration** (`:141-142`) so the mid-turn budget accounts for it.
- `compileGoalIntentLLM` survives ONLY as the D7 fallback; removed from the prose path and the clarify-resume path.
- **INV-4 (ADR-080) preserved:** the Judge still receives NO workspace/project instructions — `buildJudgeUserContent` is untouched. (Grill-verified: the relocation strengthens the invariant, since the instructions now reach only the work turn.)

### D5 — CHAT-LISTING SURFACE + STEERING: assumptions, not gates; the confirmation ritual is deleted

- **Render path is the typed frame, not tool args `[G-M10]`:** on every successful `set_goal` (register or update) — and on marker-path activation/restate — the engine emits the `goal_status` frame in state `active` **with `criteria`, `dod`, and `definition` populated** (the same optional fields the `queued` emission populates today; schema SHAPE untouched — but the queued-only description prose on those three fields in `contracts/components/schemas/GoalStatusFrame.yaml` is updated, regenerated, and hand-synced to `contracts/asyncapi.yaml`'s inline duplicate, and `pkg/agent/goal_status_criteria_wire_test.go`'s queued-only assertion is rewritten to the new emission rule — spec-grill B5 correction). The SPA renders the record card from that frame — the redesigned flat/accordion/judgment-icon renderer (prerequisite branch, `[G-B4]`) re-keyed from "pills in `queued` state" to "the active pill carrying criteria", minus the button row. No hand-written tool-args type crosses the boundary; Constraint #8 clean.
- The agent's own prose remains free to summarize its assumptions (operator point 3); the frame-rendered card is the authoritative structured view. The backend never returns a separate full-record text echo on webchat — root cause 1 dies.
- **Channels keep a record view `[G-M10]`:** `goal_status` frames reach only the SPA (event-bus → WS); `bus.OutboundMessage` is text-only. So `formatGoalEcho` is **NOT deleted — it is re-scoped** as the channel-side record view: on a channel-origin goal session, after a successful register/update, the engine sends the formatted record (statement + criteria + DoD) as a normal channel text message. Same helper also keeps serving `/goal status`. (Its pending-confirm phrasing is rewritten; `goalEchoFallbackNote` dies with the front-path compile.)
- **Steering replaces confirming:** an ordinary user message that changes direction reaches the working agent as chat; the agent updates the record via `set_goal(mode: update)`; the diff (computed backend-side, D2) surfaces in the tool result and the refreshed frame. No confirm word, no pending amendment state.
- Frontend deletions (D9 details): the button row + `sendMessage('confirm')` wiring, the `queued`-state rendering branch, `useGoalCompilingIndicator`, `GoalAmendmentDiff.tsx` + its dormant re-exports.
- Defensive store hygiene: the SPA's `goal_status` handler evicts any `'_default'`/empty-id pill when a keyed frame for the same session arrives.

### D6 — KEEPER REPAIRS: same claim-or-idle architecture, three fixes

The claim-or-idle design (`goal_triggers.go`: judge fires only on evidence-backed claim or idle settlement; bounce economics; typed `waiting_on_user` pause; expiry sweep) is kept — operator-confirmed. Repairs:

- **D6a — in-flight suppression.** A live turn for the goal's session counts as activity: idle settlement is suppressed while one exists and the quiet window re-arms on turn end. **Mechanism, named `[G-M8]`:** `al.activeTurnStates` is keyed by `sessionKey`, the keeper iterates transcript session IDs — resolution is a `Range` scan matching `turnState.transcriptSessionID` (existing precedent: `pkg/agent/cancel.go` `:1102`). **A delegated child sub-turn counts as parent activity** (its live turn is reachable via the same scan; a goal whose agent is waiting on a delegate is working, not idle). **Parked-card case, defined `[G-M8]`:** goal active + a parked AskUserQuestion pending → idle settlement AND the D6c nudge are both suppressed (the goal is typed as waiting-on-user in the same sense as the `waiting_on_user` marker pause); the expiry sweep still bounds total lifetime.
  **Zero-output idle on a RECORDED goal (spec-grill B1/B2 correction; refined round 2):** "zero adjudicable output" is the named triple — zero evidence records ∧ zero **goal-scoped** workspace diff ∧ zero transcript output — where transcript output is counted **across the goal session AND its delegated descendant sessions** (ADR-057 gives children their own transcripts; a goal whose agent delegated all its work is WORKING, not empty — this case must never match), and the diff term is scoped to **this session's write set since this goal's start / last push boundary** (`AttemptDiff` takes a scope argument; the current unscoped `AttemptDiff(nil)` would let a co-tenant session's diff on a shared workspace mask this goal's emptiness — round-2 B-4; on an unbound chat goal the diff term degenerates away and the triple is a pair, stated deliberately). When the triple genuinely holds at idle on a goal WITH a registered record: no verdict, no round consumed; the keeper dispatches a continue-push (same Ralph mechanism, stamped sender), **at most 2 consecutive times** — the streak is **persisted on the goal record** (`GoalZeroOutputPushes`; an in-memory counter would reset on every gateway restart and re-open the unbounded loop — round-2 B-1), reset to 0 whenever the triple evaluates false at an idle or a successful `set_goal` write lands, and paced on the existing idle quiet-window constant (no new cadence knob). If the triple still holds at the NEXT idle after the second push, idle settlement adjudicates normally (a fail-closed verdict is then legitimate and consumes a round) — the standard rounds bound takes over. A recordLESS quiet goal routes to D6c (its own N=2 ladder), never here.
  **Keeper routing durability (round-2 M-9):** the goal's routing (channel/chat/session-key/agent) recorded by `recordGoalRouting` currently lives only in an in-memory map — a restart silently disables the keeper push AND the channel record echo for a long-running channel goal. The route is persisted with the goal record and rehydrated on demand (`routeFor` falls back to the persisted route); a genuinely missing route WARNs and surfaces in `latest_reason` instead of degrading silently.
- **D6b — un-wedge the Ralph push (the push already exists) `[G-B3]`.** `runGoalAdjudication` already steers on unmet (`deliverSteer(goalSteeringPrompt(...))` `:444-446`) with the per-criterion missing-list (`goalVerdictReasonText`), and the idle path already wires delivery (`idleSteerDeliverer` → `asyncNotifier`). **The actual defect is an origin gate:** the idle-steer turn is published with `Sender.CanonicalID = "async:goal_idle_settle"` and `UserInitiated=false`, and `checkGoalLoopAfterTurn` (`goal_loop.go` `:1124`) accepts only user-initiated turns or `goalLoopFollowUpSenderID` (`"system:goal_loop"`). The steer turn is therefore dropped at the gate: activity never bumps, `goalMarkIdleSettling(sessionID,false)` never runs, and `maybeSettleGoalIdle` returns forever after — **the idle keeper fires exactly once per goal, then wedges** (and that turn's `GOAL_STATUS:` markers are never parsed). Fix: the idle-steer dispatch is stamped as `goalLoopFollowUpSenderID` (one canonical goal-loop sender for every keeper-originated turn), restoring the re-arm the code's own G-2 comment already claims. Regression test required: idle-steer turn → activity bumped, settling flag cleared, second idle cycle possible.
- **D6c — the no-record nudge.** D3 predicate true + no parked card + turn machinery quiet → the keeper's action is NOT a judge round (nothing to judge) but a nudge turn (stamped `goalLoopFollowUpSenderID`; forced pair on webchat, rubric-only elsewhere per D3). After **N=2** nudges without a registration, the engine runs the D7 fallback compile once and registers its output itself (record `author` marked as engine/fallback). The invariant — every active goal ends up with a judgeable record — holds in code. (Nudge counting is only sound once D6b un-wedges the loop; the two repairs ship together.)

### D7 — FAST LANE: remaining engine-side goal LLM work runs on the Judge agent's model

- The D6c fallback compile — the only surviving engine-invoked goal LLM call — resolves provider/model from the **Judge system agent** (`GetRegistry().GetAgent(string(coreagent.IDJudge))`, the same resolution `runVerifierAdjudication` uses at `verifier_adjudication.go` `:910`). Implementation is a one-argument change at `goalCompileLLMCall`'s instance read (grill-verified). Rationale (operator): judge-profile work — structured extraction, no creativity, bounded output — belongs on a fast model; one knob governs all of it.
- **Degradation, stated `[G-m12]`:** if the Judge instance or its provider is nil, `compileGoalIntentLLM`/`goalCompileLLMCall` already fall back to the deterministic marker parser — for a prose intent that yields a thin marker-only record. This case logs at WARN (D8). And today the knob changes nothing: the Judge agent's model is unset and inherits the slow default — **operator action item:** set the Judge agent to a fast model.

### D8 — GOAL-EVENT LOGGING: the events that were missing, not duplicates of the ones that exist

`[G-m14]` The idle path already logs at INFO (`goal_triggers.go` `:549` idle-settle firing; `goal_loop.go` `:1200` claim dropped); the 2026-09-07 trace was blind to them because of the log LEVEL, and blind to everything else because those events don't exist. Those two existing lines gain a `goal_id` field (they carry only `session_id` today) so the whole goal narrative is joinable on one key. D8 adds the missing ones — activation, `set_goal` register/update with validation outcome + diff summary, forced-pair door taken (or forcing skipped: policy-denied / non-web / CLI provider), keeper nudge count, idle suppression reason (in-flight turn / parked card / zero-output route), fallback-compile invocation — at INFO under `component: "goal"` with `session_id`/`goal_id`, **without duplicating the existing lines**. Operationally critical events — fallback compile invoked, N-nudge exhaustion, Judge-instance-nil degradation, forcing defeated by `extra_body` — log at WARN.

## What survives / what dies

**Survives unchanged:** the compiled-goal record shape (ADR-080), `NormalizeCriteria`/`validateCriterion`/`InferJudgment`, the DoD floor, feasibility vetting, the `define-goal` skill, INV-4, the judge's evidence assembly, claim-or-idle + bounce + `waiting_on_user` + expiry sweep + rounds accounting, `/goal clear`, the marker-only activation path (with `definition` legitimately empty on marker records — the existing Prompt/Intent fallback, round-2 B-3), the AskUserQuestion tool/card/registry (web-only, as ruled), the goal pill tray (active/judging/done/failed), `formatGoalEcho` (re-scoped: channel record view + `/goal status`), `diffGoalAmendment` (re-homed: `set_goal(mode:update)`'s differ), **`cancelOrphanedClarifyCard` (re-homed, round-2 M-6: its old call sites die with `emitGoalClarificationCard`; its NEW call sites are new-goal activation and `/goal clear`, cancelling a parked card WITHOUT dispatching a resume — via `CancelOnSessionStop`-style non-resuming cancellation, never `CancelByUser` which injects a resume turn)**. `/goal status` survives as a surface but is REWRITTEN (pending branches deleted; record summary added — a NEW `formatGoalEcho` call site).

**Dies (deleted in full — see D9):** the front-path `compileGoalIntentLLM` invocation + clarity gate + 20k-window feed (call survives as D7 fallback only), the pending-confirm state and its meta-field semantics, `applyGoalPendingReply`'s confirm branch + `IsGoalConfirm`/`confirmGoalAliases`/`ConfirmGoalWord`, `confirmPendingGoal`, `proposeGoalAmendment`, `emitGoalClarificationCard` + the goal-side `goalClarificationRecord` (D3's predicate replaces the correlation), `formatAmendmentEcho`, `goalEchoFallbackNote`, `isGoalConfirmVerb`, the `queued` emission, **`pkg/agent/goal_pending_note.go` in full** (`[G-M5]` — gated on `GoalPendingJSON`, references `ConfirmGoalWord`; leaving it is a compile error, its two call sites at `pkg/agent/loop.go` `:9326` and `pkg/agent/midturn_budget.go` `:141` are unwired), `formatGoalStatementAndCriteria` *if* `formatGoalEcho`'s re-scope leaves it callerless (fold or keep per implementation — no callerless survivor), the frontend confirm row + `sendMessage('confirm')` + queued rendering + `useGoalCompilingIndicator` + `GoalAmendmentDiff.tsx` and its `emptyDiff`/`GoalAmendmentDiffData` re-exports.
