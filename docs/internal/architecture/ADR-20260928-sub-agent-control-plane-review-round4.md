## New findings exposed by the corrected design

### R4-MAJ-001 — A delayed Stop can cancel a newer same-generation RESUME

| Required field | Finding |
|---|---|
| **Severity** | **MAJOR — blocks build-spec readiness.** A newer accepted resume must not be undone by an older control's delayed effect. |
| **Failure scenario** | Stop all stamps child C at generation G, then its live-cancel callback is delayed. C's old turn exits and the proposed completion path lands `stopped`, clearing the fence. A later explicit RESUME queues or starts C again at the **same G, in the same boot**. The old callback then removes C's newly queued entry or looks up its new live turn; generation equality still holds, so it aborts the resumed work. This violates D5's newer-action ordering. |
| **Evidence** | ADR D2 “Same-generation resume and restart fence”, D5 later RESUME/answer rule, D7 “underlying mechanism is unchanged”, and the unchanged-cascade Impact row. [Cancel source](/Users/danielpiatkowski/AI-Agent-Workspace/omnipus-worktrees/adr-cp-grill-r4/pkg/agent/steer_cancel.go)::`SteerCanceller.cascade`, `cancelStamped`, `Revive`, `AgentLoop.SteerGenerationCancel`; [turn registry](/Users/danielpiatkowski/AI-Agent-Workspace/omnipus-worktrees/adr-cp-grill-r4/pkg/agent/turn.go)::`AgentLoop.requestCancelForGeneration`; [admission queue](/Users/danielpiatkowski/AI-Agent-Workspace/omnipus-worktrees/adr-cp-grill-r4/pkg/agent/admission.go)::`steerAdmission.removeQueuedSession`. |
| **Certainty** | **Verified (high confidence):** callbacks carry session ID/generation; the cancel primitive checks only the currently registered turn's generation; queue removal is by session ID before that check. The cascade lock is not acquired by `Revive`. **Inferred (high confidence):** the interleaving above becomes unsafe under the proposed same-generation stopped RESUME. It was not run. |

**Why the existing fences are insufficient.** The per-record lock orders durable state changes, not delayed effects after the lock is released. The boot epoch cannot distinguish two attempts in the same boot. D2 records the intended control ID, but never binds the old cancellation callback/queue removal to that identity. D7's unchanged-mechanism instruction therefore conflicts with D2/D5; retaining the traversal does not justify retaining generation-only effect targeting.

**Required technical correction.** Keep same-generation stopped RESUME. Define an execution-attempt/control identity check, or equivalent stale-effect exclusion, for cancellation, delayed hard escalation, queue removal and stop-finalization effects. An older Stop must only affect the execution it selected; after a newer RESUME supersedes that execution, an old callback must not look up and cancel the replacement. Reuse the existing control identity where suitable rather than adding another user-visible generation. Amend the unchanged-mechanism/Impact claim and specify the check at the effect boundary, not merely before scheduling a callback.

**Required proof.** Through normal production dependencies, pause an old Stop after its durable fence and before the live effect. Let the old turn land stopped; explicitly RESUME in the same generation and boot; release the old callback. Cover both newly queued and active resumed work. The stale callback must neither remove nor abort it. Positive control: a genuinely newer Stop still stops the resumed work. Keep the no-lock-across-interrupt rule.

**Relationship to the correction:** newly identified interaction in the corrected stopped/resume design, not a claim that the existing generation-bumping implementation already exhibits the new live-turn race. Queue removal by session ID is an existing adjacent hazard to cover in the same control-identity audit, not counted as a third finding.

### R4-MAJ-002 — Final-delivery progress has no legal post-terminal persistence path

| Required field | Finding |
|---|---|
| **Severity** | **MAJOR — blocks build-spec readiness.** The newly required durable delivery protocol cannot complete through the specified lifecycle store without an additional decision. |
| **Failure scenario** | A real `LifecycleStore.Mutate` commits generation G as done/failed with its unpublished `final_delivery`. The publisher appends the exact result to the parent inbox, then tries to persist `delivery_progress` or retire the payload. Another same-generation lifecycle append now returns `ErrLifecycleTerminalImmutable`, even when outcome and message identity are unchanged. Retrying cannot make this write legal. The ADR requires durable progress/retirement but does not define another journal or a bounded exception. |
| **Evidence** | ADR D2 atomic commit and publish paragraphs; D4 lifecycle-internal `final_delivery`; D8.1/5/9; T11 and Impact's shared real-store mutation dependency. [Lifecycle store](/Users/danielpiatkowski/AI-Agent-Workspace/omnipus-worktrees/adr-cp-grill-r4/pkg/session/lifecycle.go)::`LifecycleStore.persistLocked`, `LifecycleStore.Mutate`. [An open conversation must keep the ability to delegate](/Users/danielpiatkowski/AI-Agent-Workspace/omnipus-worktrees/adr-cp-grill-r4/docs/internal/architecture/ADR-093-open-conversation-must-keep-delegation.md)::“Invariants this ADR will not break” explicitly retains terminal-generation immutability. |
| **Certainty** | **Verified (high confidence):** every same-generation append after a terminal tail is rejected, and `Mutate` uses that guard; the new progress field resides in the lifecycle outbox shape. **Inferred (high confidence):** the proposed post-commit phase fails if implemented through that store without an explicit invariant amendment. No new outbox implementation or reproduced delivery loss is claimed. |

**Required technical correction.** Define where post-commit delivery progress and replay-prevention identity live and how they are written legally. Two bounded approaches are compatible with the product decisions: keep the terminal outcome immutable and use a separate delivery-progress journal tied to the committed outbox identity, or explicitly permit narrowly validated delivery-metadata-only appends while keeping committed outcome, generation, final ID and payload identity immutable. The author must choose and state the invariant; unrestricted terminal mutations would undo the winner protection the correction just introduced.

Also specify how an undelivered final for G remains discoverable and retryable if explicit RESUME of done/failed creates G+1 before delivery finishes. A later generation must not hide the earlier committed result. This is part of the same outbox ownership/recovery decision, not a separate finding.

**Required proof.** Extend T11 through the **real store's post-terminal phase**: terminal/outbox commit, durable progress update, permitted payload retirement, restart/retry, and newer-generation RESUME while the old result remains pending. Negative controls must still reject changing the committed outcome or final identity. Merely blocking the first terminal write, checking the final state, or using a fake progress store does not exercise this gap.

**Relationship to the correction:** the round-three CRIT-001 fix introduced the terminal outbox and its post-commit progress requirement. Its publication ordering is now sound as a requirement; its persistence lifecycle is incomplete. This is why CRIT-001 is PARTIAL rather than either unchanged OPEN or fully CLOSED.
