The eight edits

  1. Acceptance criteria becomes required, using the same red asterisk the Title field already uses. The empty hint that says the task will be judged against its title and description is removed from both forms, because it teaches the fallback being closed. The create form gets a plain instruction instead.
  2. Definition of Done is added. In the create form it is a second list with the same editor. In the detail panel it appears as its own group under the criteria — that group already exists in the shipped verdict list and renders under the heading "Definition of Done"; the panel simply never passes it anything today.
  3. Verdicts render on each criterion — met, not met, or not judged yet, with the Judge's own words underneath. The rows, the ticks, the reason line and the evidence expander all ship today. What is missing is the data: every criterion is written as pending and nothing ever writes met or unmet, so the panel currently shows a column of empty circles no matter what was decided.
  4. Prompt is renamed Goal. It is called Prompt on the create form and Prompt / Instructions on the detail panel; both become Goal. This is the field that becomes the goal record once the task starts its own session, so the form should say so rather than describing the plumbing. It also stops reading as free instructions sitting next to the criteria that judge them.
  5. The checklist is relabelled Todos in both forms, and its placeholder with it. The field is called todos everywhere below the surface — the data, the API and the component's own notes all say todos — so the label was the only place the other word survived.
  6. Title becomes editable in the detail panel. It renders as plain text today with no edit control anywhere in the product, so a task can be named once and never renamed. The API has always accepted a title change — the update request carries a title field and the handler applies it — so this is a missing control, not a missing capability.
  7. Plan is added to the create form. The detail panel has a Plan picker; the create form has none and silently inherits whichever plan the board is filtered by. Create from an unfiltered board and the task lands with no plan, and the only way to give it one is to save it and reopen it.
  8. Trigger is removed from both forms. A normal task has no timer. It starts one of three ways — someone presses Start, an agent starts it, or a plan reaches it — and none of those is a schedule. Time-based starts are the calendar's job, and the board and list already exclude every task that has one. So the field could only ever do harm here: on the detail panel, picking "Once" writes a default time you never chose, at which point the task counts as scheduled, drops off the board and list, and the field turns into a read-only link to the calendar. The choice ejected the task from the surface you were standing on. The field goes; the calendar keeps the capability.

Moved out: the attempt limit is not set here. It is one global goal setting under Settings → Performance. The panel keeps its read-only "attempt 2/3" line, which it already shows. Verified in code: a task's attempt count is "the current run's attempt index within its goal loop", and its ceiling is "the attempt ceiling before the goal loop gives up" — so the task retry and the goal retry are the same counter, not two.

Removed: the Judgment selector (boolean / quantitative / artifact). The server already forces it for both check kinds — a technical check is always boolean, an action-count check always quantitative — so it was never a real choice there. On a prose criterion its only functional use routes to an inferred file check, which the "never synthesise a check from wording" decision retires. The Judge classifies what kind of claim a criterion makes from its wording. Whether the field also leaves the data model is a separate decision, flagged not taken.

Unchanged in the create form: Priority, Tags, Agent, Depends on, Due date and the three footer buttons.

Unchanged in the detail panel: the autosave line, Priority, Status, Workspace, Plan, Tags, Agent, Depends on, Due date, Stop, Open in Chat, Result, Runs, Artifacts, the five metadata rows and Delete. The panel autosaves every field; it has no footer buttons. The criteria editor itself is unchanged too, including the optional technical check and action-count check, which keep their existing wording and stay attached to a criterion rather than standing on their own.
