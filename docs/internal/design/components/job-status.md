# Job Status

`JobStatus` is caller-controlled across queued, running, progress, paused, failed, complete, and cancelled. It shows a percentage only from finite in-range progress and retains the last real value only for the same job identity and scale when later reports become unknown. Supply `jobKey` when the same component instance can render successive jobs. A terminal-to-active transition also resets retained progress.

Active work escalates using the shared 10,000ms loading-escalation token: known progress remains determinate with stall copy; unknown progress remains indeterminate. The stall clock restarts only when the informative progress value changes; any two unknown or invalid reports (missing, `null`, `NaN`, non-finite) count as unchanged, so a stable invalid value such as a repeated `NaN` never postpones escalation and a rerender never clears an existing warning. Paused stays active for timing but never claims work continues: its escalation copy is paused-specific ("Paused; progress is unavailable." for unknown progress, "Paused; no progress reported recently." when holding a known value) while the caller-controlled status is untouched. A valid past timestamp can cause immediate escalation, a future timestamp is clamped to observation time, and a missing or invalid timestamp starts the clock when observed. Terminal state changes are announced and stale stall copy disappears immediately. Cancel and background apply to active states; Retry applies to failed or cancelled states.

The browser contract targets Cancel as the representative caller-controlled action; Run in background remains a separate valid action. Determinate progress translates a full-width fill inside an `overflow: hidden` track, so overflow measurement must use its clipped visible intersection rather than treating the fill's unpainted layout box as page overflow.

Persistent visually hidden live regions announce non-failure state and stall changes politely and failures assertively. Visible state and stall text remains presentation content rather than a second live region, preventing duplicate announcements while preserving the existing layout.
