# Bounded browser state delivery

The approved design adds two replaceable connection-local slots: the newest tab snapshot and the newest video/frame-health snapshot. A single buffered wake signal tells the existing WebSocket writer to consume pending state. Publications must return without waiting for a slow viewer's critical-message queue or network. Discrete control/signalling transitions keep their existing critical path.

An attachment context fences each publication at storage and again when the writer consumes it. A packet already handed to the transport can arrive after attachment replacement, so existing session/capture/generation identity remains the receiver's final fence. No attachment mutex is held across network I/O. Pending storage is fixed at two frames plus at most one frame already being written.

Tests derive from these bounds: fill the critical queue and publish a burst; retain exactly the final snapshot of each kind; cancel before storing and after storing; verify bounded wake coalescing and rearming; reject closed-connection publication; and deliver both latest state and a discrete control transition over a real socket. The initial compatibility implementation routes publication through the old critical queue, providing a concrete failing baseline. Mutations must independently remove a lifetime fence, remove fairness, or break the writer wake path and fail the relevant assertions.

GitNexus preflight: the guessed `writeLoop` name was absent; a query resolved the exact `BrowserWSHandler.writePump` symbol. `writePump` and `browserWSConn` each report LOW risk with one direct caller in ServeHTTP. The sendCritical comment update reports LOW risk with one direct caller and 21 transitive symbols; its delivery behavior is unchanged.

Pending kinds are consumed fairly: a stream of new tab snapshots must not starve a video/frame-health snapshot. A two-position cursor alternates pending kinds, so an already-pending video snapshot is served within two latest-state writes. Tests also reject unknown slot kinds and marshal failures explicitly.

Caller integration must retain the attachment scope from observer registration and publish complete snapshots. In the existing attach path, the initial tab callback fires before attachment binding; the caller therefore needs an epoch-scoped pending lifetime adopted by binding, or equivalent initial-event buffering. Looking up the current attachment only when an old callback fires is insufficient. Replacing a video/frame-health snapshot does not merge partial fields, so capture/generation/CSS identity must accompany health snapshots where applicable. Parent owns this observer wiring.

## Observed verification

The compatibility baseline failed the intended behaviors (exit 1, 7.254s): publication waited on a full critical queue; six snapshots remained instead of two; canceled attachments survived both admission and dequeue; pending state did not wake the writer; closed connections and invalid kinds/marshal failures were reported as accepted. The existing-path real socket delivery and fairness guards already passed that baseline.

The implemented two-slot path passed the focused race/shuffle selection (exit 0, 19.753s), including the new latest-state cases and existing browser WebSocket authentication, input/control/tab/viewport and reader-responsiveness regressions. An additional deterministic boundary case cancels an old attachment and publishes its replacement while the old frame is being encoded; completing the old encoding must neither be accepted nor overwrite the replacement snapshot. All three deliberate faults were caught with behavioral failures: removing the post-encoding attachment fence, always prioritizing tabs, and ignoring writer wake notifications. Each fault was restored before the next run. The final restored latest-state suite passed (exit 0, 10.666s), including the strengthened encoding-boundary test. These results establish the bounded connection delivery behavior; integrated observer wiring, full CI, and live UI/runtime validation remain parent-owned and are not claimed here.
