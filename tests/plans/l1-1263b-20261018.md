# #1263-B RED acceptance map — 2026-10-18

## Behaviour and authority

Task and plan session chains never ask a person for tool approval. Calls settled by Auto, an operator rule or a standing grant execute; otherwise an Ask call is refused visibly without waiting. A helper inherits the chain's root origin, not the last sender or the fact it is a child. Interactive chat chains still ask.

## Unit boundary and instruments

Real: entry-point dispatch, durable task/plan/session stores, turn construction, delegate/session-launch propagation, tool policy/Auto selection, actual write_file/delete_task/bash execution, transcript writes, denial classification, and the production approval registry/adapter and WebSocket constructor. A deterministic model-provider fixture sits at the paid network edge and requests the specified tools; it records the exact tool results rather than deciding policy. Execution controls use temporary files/output, not a stubbed policy decision. No test stamps unattended state on behalf of the entry point being tested.

The shared fixture drives isolated task roots; the MAIN-mode test additionally installs the real gateway task-main resolver and checks that the task really is its assignee main's child. Plans start through real execute_plan and one production PlanEngine tick; no fake member dispatcher or Judge verdict is used. Helper launches use the actual delegate tool, launcher and lifecycle stores. Human re-entry uses real WebSocket chat intake plus the real inbound pump; system re-entry uses the async-origin inbound envelope. Model-edge barriers make per-chat switch/grant installation and parent/child ordering deterministic.

Tests must use isolated temporary data roots and must never read or write `/Users/danielpiatkowski/.omnipus`. All goroutines must be joined or drained before temporary-root cleanup. A forbidden approval is an immediate, named failure (the request/frame/pending entry is evidence), not a generic timeout. The interactive control proves the approval observer can actually detect a request. No sleeps are used as proof of absence: zero approvals is asserted after a turn completion or a positively observed forbidden request.
