# #1263-B RED acceptance map — 2026-10-18

## Behaviour and authority

Task and plan session chains never ask a person for tool approval. Calls settled by Auto, an operator rule or a standing grant execute; otherwise an Ask call is refused visibly without waiting. A helper inherits the chain's root origin, not the last sender or the fact it is a child. Interactive chat chains still ask.

## Unit boundary and instruments

Real: entry-point dispatch, durable task/plan/session stores, turn construction, delegate/session-launch propagation, tool policy/Auto selection, tool execution, transcript writes, denial classification, and approval registry/adapter where exposed by the fixture. A deterministic model-provider fixture sits at the paid network edge and requests the specified tools; it records the exact tool results rather than deciding policy. Execution controls use temporary files/output, not a stubbed policy decision. No test may stamp unattended state on behalf of the entry point being tested.

Tests must use isolated temporary data roots and must never read or write `/Users/danielpiatkowski/.omnipus`. All goroutines must be joined or drained before temporary-root cleanup. A forbidden approval is an immediate, named failure (the request/frame/pending entry is evidence), not a generic timeout. The interactive control proves the approval observer can actually detect a request. No sleeps are used as proof of absence: zero approvals is asserted after a turn completion or a positively observed forbidden request.

## Fixed refusal oracle (literal values, not implementation constants)

| Surface | Expected text |
|---|---|
| Model tool result | `Task and plan runs never ask a person for approval. This call needed approval and was refused. Do not retry; finish what you can and report what was blocked.` |
| Transcript tool row | `Not run: needs approval, and task and plan runs never ask.` |
| Denial table reason | `auto-denied: ask-policy tool not allowed in a task or plan run` |
| Audit | Events `tool.policy.deny.attempted` and `tool.policy.ask.denied`, task/plan-specific reason (not scheduled or user); no missing-cron-identity warning |

The amendment requires a new audit reason constant but does not prescribe its serialized spelling. Do not invent one; assert its task/plan semantics and absence of the old scheduled reason. If the implementation contract leaves that unobservable, report the gap.
