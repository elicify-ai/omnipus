Calendar & Automations

The Calendar makes "when" intuitive for everyone. Automations (Trigger → Action) are the engine that already exists — surfaced. Both are scoped to the current workspace (set by the sidebar switcher).

The friendly view

Calendar — native + import, per workspace

All (default) + 4 category filters · the sidebar workspace switcher · imported & delegated calendars overlay read-only.

① iCal subscribe universal

Paste a .ics URL → read-only overlay, server-refreshed. Zero credentials. Pure-Go: golang-ical + rrule-go.

② Provider OAuth two-way

Google (then MS Graph): free/busy for agents + write-back. syncToken + watch webhooks (7-day renewal).

③ CalDAV self-host

Nextcloud / Fastmail / iCloud. Lower priority — vendor quirks, poll-based.

Tasks gain start_date + due_at + recurrence (the model has zero date fields today). A recurring task = a task + a repeating trigger. Expand RRULE against the IANA tz database — DST is the #1 calendar bug.
The engine, surfaced

Automations — Trigger → Action

Omnipus already funnels almost every trigger through one path (a message → an agent turn) over a real EventBus. We surface it as readable rules.

Triggers — "when…"

  • ⏰ Time — every Mon 9am · cron · interval engine exists
  • ⚡ Event — task done · run failed · milestone due bus exists
  • 📥 Connection received — email · webhook · message seam exists
  • 🗓️ Calendar — event starts / nears new

Actions — "…do this"

  • 🤖 Run an agent exists
  • 📋 Run / create a task new link
  • 🛠️ Invoke a tool / MCP MCP today
  • 📤 Send via a connection · 📡 webhook-out · 🔔 notify
The lowest-friction first event: task_status_changed is already defined in the contract with no producer — a ready slot. schedule_failed is already a live event. Heartbeat / "dreaming" = automations flagged system:true, shown in the Calendar's System filter.

Automations are authored by the Assistant (Mia) from chat ("want me to do this every morning?") and run by the platform — there is no separate automation agent (no Forge / Max persona).

Opening up

Zapier / n8n / Make — open primitives

External → Omnipus ~70%

REST exposes create/run task, schedule, send-chat. Gap → scoped API keys. Or POST to an inbound webhook channel.

Omnipus → External new

A webhook-out action: on an event, POST signed JSON (retry + log). Generalizes cron's Deliver/Channel.

Agent → External MCP today

Agents already reach Zapier/n8n + 1000s of actions via MCP — the established outbound path.
