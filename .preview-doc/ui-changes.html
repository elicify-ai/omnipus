Screen 1 · the frame

Global shell & navigation

The sidebar restructures around workspaces as the primary nav. Chat, Tasks, Calendar, and Team move from top-level routes into tabs inside the active workspace. Global reusable assets (Agents, Connectors, Skills & Tools, Settings) remain in the sidebar.

As-is exists

Top-level screens: Chat, Agents, Channels, Skills, Tools, Monitor (with Schedules + Token Usage), Tasks/Projects, Command Center, Settings.

To-be

Sidebar = WORKSPACES primary list (My Workspace ⭐ + named + Archive) + global libraries: Agents (library + Workspace Teams) · Connectors · Skills & Tools · Settings · Sign out. Channels → Connectors. Chat → workspace Chat tab. Tasks → Board/List/Graph/Calendar tabs. Calendar → workspace tab. Automations → REMOVED (tasks with triggers replace it). App default front door = My Workspace → Chat → Mia.

When: IA reframe (workspace tabs + sidebar restructure) = v0.1.0

Screen 1b · first run

Onboarding

A single-user first-run flow that ends by introducing the agent that's yours.

As-is exists

Technical bring-up: a bearer-token / admin-bypass path (--allow-empty, dev_mode_bypass) — no guided setup, no password, no first agent.

To-be

A 3-step guided flow: 1. "What should I call you?" (your name) → 2. set one password → 3. add a model key. Then it auto-provisions your Assistant in My Workspace — "meet your Assistant". Single user, one password throughout.

Screen 2 · the default workspace tab

Chat — workspace view

Chat is no longer a global front door — it is the default tab of the active workspace. You're always in a workspace; picking a workspace sets the full context (chat, tasks, memory, team). The app's default front door is My Workspace → Chat → Mia.

As-is exists

Chat-first, but a global top-level route. A handoff agent-switch indicator; spawned subagents render as a collapsible SubagentBlock; tool calls visible & collapsible.

To-be

Chat = the default (first) tab of a workspace. The agent picker is scoped to the workspace's team (only agents assigned to this workspace appear). Every session is tagged with the active workspace_id. The conversation-history panel is filtered by the active workspace — you see only this project's conversations. A unified call-tree activity view — handover + delegation + tasks in one timeline. Plus multimodal: a mic (voice-in), a ▶ play per agent message, and inline generated images.

When: workspace-scoped chat tab + team-scoped agent picker + session workspace tag = v0.1.0  ·  richer call-tree + multimodal = v1.0.0

Screen 3 · the global library

Agents

The Agents screen is a global library — agent definitions live here, independent of any workspace. It has two views: the agent library (all agents, filterable by workspace) and Workspace Teams (the per-workspace delegation graphs).

As-is exists

Agent list, create, profile, ★ default. No delegation UI at all.

To-be

Two views: Agents (library) — all agent definitions with filter [All | by workspace]; editing an agent here applies globally everywhere it is used. Workspace Teams — an index of every per-workspace team; click a team → the workspace's delegation graph (same graph as the workspace Team tab, one source of truth). Roster sections: MAIN AGENTS — 4 cores (Mia⭐ · Jim · Ray · Ava) in a "BUILT-IN ROSTER" accordion (adaptive expand) + custom Main agents; SUBAGENTS — seeded specialists (Planner / Explorer / Researcher) + custom subagents: no heartbeat · delegation-only · not chat targets. Editing is via the existing AgentProfile slide-over from anywhere you see an agent.

Screen 5 · workspace tabs

Tasks — Board · List · Graph · Calendar

Tasks are no longer a separate top-level route. They live as four tabs inside the active workspace: Board (kanban), List (flat), Graph (dependency DAG), and Calendar (recurring tasks by date). A single unified task model; one store.

As-is exists

Two separate task stores (GTD board + workflow queue). Board + List + Execution views. No Graph view. No dates. No dependencies visible.

To-be

One unified task entity, 7-state lifecycle (inbox · next · planning · in progress · blocked · done · failed). Four workspace tabs: Board (kanban by status; delegation roll-ups: parent card shows "▸ N sub-agents" badge, children nested/collapsed) · List (flat/filterable) · Graph (task DAG — tasks as nodes, blocked_by as edges) · Calendar (recurring/scheduled tasks by fire date). Tasks carry workspace_id, trigger, due, action, blocked_by, parent_task_id. Delegated tasks are visible cards on the board.

Screen 6 · removed surface

Automations → removed

The Automations screen is removed. Automation is no longer a separate concept — it is a property of a task. Tasks with time triggers (once / every / recurring) replace the old schedules/automations surface. The Calendar tab (inside each workspace) shows recurring tasks by date. Heartbeat is a per-agent recurring task (visible in the agent profile, hidden from the board).

As-is exists

A schedules list (cron); Monitor token-usage. Automations screen exists as a stub pointing at Command Center.

To-be

No Automations screen. Schedules/automations are expressed as tasks with triggers (trigger: {kind: once|every|recurring, …}) and live on the Board/Calendar. Heartbeat = a per-agent recurring-trigger task (surface: heartbeat) — shown on the agent profile, filtered out of the board. The sidebar Automations entry is removed entirely.

When: Automations screen removed + tasks with triggers replace it = v0.1.0  ·  workflow engine (event triggers, conditional edges, rule builder) = v0.3+

Screen 7 · workspace tab

Calendar — workspace tab greenfield

Calendar is a tab inside each workspace (not a standalone top-level route). It shows recurring and scheduled tasks for that workspace by their fire date. Previously an orphan route, now properly surfaced as the fourth workspace tab.

As-is partial

A calendar view exists but is an orphan route — linked from nowhere in the sidebar. Per-workspace, but unreachable in normal navigation.

To-be

Workspace Calendar tab — shows tasks with time triggers (once / every / recurring) scoped to the active workspace by fire date. Heartbeat tasks are hidden (surface: heartbeat) — they are shown only on the agent profile. Import via iCal → provider OAuth → CalDAV later. The tab is always present; if no scheduled tasks exist, shows an empty state with a + Task shortcut.

Screen 7b · workspace tab

Team — workspace tab greenfield

Each workspace has a Team tab — the per-workspace delegation graph. Adding an agent to the team and setting delegation edges are the same action.

As-is partial

Trust-graph matrix in the Agent Delegation tab (global, per-agent). No per-workspace team concept.

To-be

Workspace Team tab = the per-workspace delegation graph. Nodes = agents on this project. [+ Add agent] / remove = add/remove a node = team membership. Edges = delegation: drag to connect; click edge → set modes/depth. My Workspace is pre-seeded with the default team (4 base + Planner/Explorer/Researcher) + default edges. The same graph is also reachable from Agents → Workspace Teams (one source of truth). Editing an agent opens the existing AgentProfile slide-over.

Settings

Two halves: a top-right Profile menu for personal settings, and Settings for the app's config (sensitive sections re-type the password). User management collapses — single user.

User management is gone (single user) — the only account action is password reset, in Profile.

The point

What ships in v0.1.0 is real, not placeholder

Every v0.1.0 row above sits on actual data — because v0.1.0 lands the structural shapes first, the UI is never thrown away later.

v0.1.0 lands the data shapes and IA the rest builds on:
  • The workspace-as-project IA — chat, tasks, calendar, and team as workspace tabs; WORKSPACES as primary nav; Automations removed.
  • The Workspace scoping key (workspace_id) threaded through tasks, memory, calendar, sessions (tag), and connections.
  • The unified task model — one store, 7-state lifecycle, unified fields (action · trigger · blocked_by · parent_task_id · workspace_id).
  • The Connection-as-instance model — capped at one per type, but the instance shape is real.
  • The agent kind taxonomy (Main / Subagent / subagent_3p) + seeded specialists (Planner / Explorer / Researcher).
  • The per-workspace delegation graph (Team tab + Agents → Workspace Teams) — one source of truth.

Because the shapes are correct on day one, the v0.1.0 UI sits on real data and is not reshaped later — later releases add behavior (workflow engine, OAuth, rule engines, multi-instance), not new structure. See the roadmap for the release sequence and the blueprint for the underlying data model.
