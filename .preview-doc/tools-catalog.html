Builtin Tool Catalog

Every tool compiled into the single Omnipus binary — 70 builtins, no plugins required. The Tools page covers the provider pattern (search · voice · image); this page is the reference list: what each tool does and who can call it. Generated from the live tool registry (GET /api/v1/tools).

70 builtin tools 26 general · 44 system.* scope: core · general

Scope — general tools are available to any agent; core tools are reserved for the built-in roster (Mia · Jim · Ava · Ray) and only reach a custom agent when you explicitly allow them in its tool policy. MCP-server and skill tools layer on top of these at runtime.

General builtins

Files

Read, write and edit files in the workspace.

ToolScopePurpose
read_filegeneralRead the contents of a file. Supports pagination via `offset` and `length`. Word (.docx), PowerPoint (.pptx), Excel (.xlsx), and PDF (.pdf) documents are automatically decoded to plain text; for these, `offset` and `length` count characters of extracted text rather than raw bytes.
write_filecoreWrite content to a file. If the file already exists, you must set overwrite=true to replace it.
edit_filecoreEdit a file by replacing old_text with new_text. The old_text must exist exactly in the file.
append_filecoreAppend content to the end of a file
list_dirgeneralList files and directories in a path
General builtins

Shell & code

Run commands — foreground, background sessions, or interactive PTY.

ToolScopePurpose
execcoreExecute shell commands. Use background=true for long-running commands (returns sessionId). Use pty=true for interactive commands (can combine with background=true). Use poll/read/write/send-keys/kill with sessionId to manage background sessions. Sessions auto-cleanup 30 minutes after process exits; use kill to terminate early. Output buffer limit: 1MB.
General builtins

Web

Reach the internet — search, fetch a page, or serve a preview the user can open.

ToolScopePurpose
web_searchgeneralSearch the web for current information. Supports query, count, and an optional temporal range filter. Returns titles, URLs, and snippets from search results.
web_fetchgeneralFetch a URL and extract readable content (HTML to text). Use this to get weather info, news, articles, or any web content.
web_servegeneralServe a directory or run a dev server from the agent workspace. Static mode (no command): registers the directory as a static website. Dev mode (with command): starts a dev server (vite/next/astro/sveltekit dev) and proxies it. Returns a /preview/<agent>/<token>/ URL. Dev mode is Linux only.
General builtins

Memory

Durable, file-based memory — no embeddings. Save, recall, and reflect.

ToolScopePurpose
remembergeneralPersist a fact, decision, reference, or lesson to long-term memory. Use category 'key_decision' for decisions made, 'reference' for reference information, or 'lesson_learned' for retrospective lessons. Each memory is stored as a structured file with full metadata. Use room='shared' to write to the workspace shared room (visible to all agents in this workspace), 'private' for agent-only memory. Default: shared when in a workspace session, private otherwise.
recall_memorygeneralSearch durable long-term memory. Returns matching entries newest-first. Use this when you need to recall a past decision, reference, or lesson. Use room='both' (default) to search all available rooms, 'private' for agent-only, 'shared' for workspace-wide memories.
retrospectivegeneralRecord a session retrospective after confirming its contents with the user. Captures what went well and what needs improvement for future reference. Call this at the end of a productive session after the user has reviewed the summary.

General builtins

Delegation & messaging

How an agent engages teammates, sub-agents and the user.

ToolScopePurpose
agent_listgeneralList all available agents with their IDs and names. Use this to resolve agent names to IDs before delegating tasks.
handoffcoreHand off the conversation to a specialist agent. The user's subsequent messages will go to the target agent.
spawncoreSpawn a subagent to handle a task in the background. Use this for complex or time-consuming tasks that can run independently. The subagent will complete the task and report back when done.
spawn_statuscoreGet the status of spawned subagents. Returns a list of all subagents and their current state (running, completed, failed, or canceled), or retrieves details for a specific subagent task when task_id is provided. Results are scoped to the current conversation's channel and chat ID; all tasks are listed only when no channel/chat context is injected (e.g. direct programmatic calls via Execute).
subagentcoreExecute a subagent task synchronously and return the result. Use this for delegating specific tasks to an independent agent instance. Returns execution summary to user and full details to LLM.
return_to_defaultcoreReturn the conversation to the default agent. Clears any active handoff override for this session.
messagegeneralSend a message to user on a chat channel. Use this when you want to communicate something.
send_filecoreSend a local file (image, document, etc.) to the user on the current chat channel.

system.skill.* — Author, edit, install, search and remove skills (the system-agent variants).

ToolScopePurpose
system.skill.createcoreAuthor a NEW skill (procedural memory). Writes a SKILL.md to the user skills directory; the write is consent-gated and versioned. Parameters: name (required, alphanumeric+hyphens), content (required, full SKILL.md including YAML frontmatter with name and description).
system.skill.editcoreEdit / refine an EXISTING skill (self-improvement). Snapshots the prior version for rollback, then writes the new SKILL.md. ToolScopePurpose

Parameters: name (required, the task title), description (optional), prompt (optional, agent instruction), workspace_id (required, from system.workspace.list), agent_id (optional, agent to assign), status (optional: inbox=new/untriaged, next=ready, planning, in_progress, blocked, done, failed — defaults to inbox), due (optional, RFC 3339 due date/time), blocked_by (optional, array of task IDs this task is blocked by).
system.task.deletecoreDelete a task. Parameters: id (required), confirm (bool, must be true).
system.task.listcoreList tasks with optional filters. Parameters: workspace_id, agent_id, status (all optional).
system.task.updatecoreUpdate an existing task. Call this to change status, reassign, rename, or link to a workspace. Use system.task.list first to find the task id. Parameters: id (required, from system.task.list), name, description, prompt, workspace_id, agent_id, status (inbox/next/planning/in_progress/blocked/done/failed), due (RFC 3339), blocked_by (array of task IDs, replaces existing list). system.workspace.* — Manage Workspaces — the one container that holds tasks, memory and connections.

ToolScopePurpose
system.workspace.createcoreCreate a new workspace to group related tasks. Call this when the user mentions starting a new workspace, initiative, or area of work. Returns the created workspace's id — pass this id to system.task.create when creating tasks for the workspace. Parameters: name (required, workspace title), description (optional, free text), core_team (optional, list of agent IDs associated with this workspace), repository (optional, git URL).
system.workspace.deletecoreDelete a workspace and all its tasks. This is irreversible — all GTD tasks belonging to the workspace are permanently deleted. Call system.workspace.list first to find the workspace id. Requires confirm:true. Parameters: id (required), confirm (bool, must be true to prevent accidental deletion).
system.workspace.getcoreGet a single workspace by ID including its live task count. Use this to refresh workspace data after creating tasks. Parameters: id (required, from system.workspace.list).
system.workspace.listcoreList all active workspaces with their task counts. Call this to find workspace ids before calling system.task.create, system.task.list, or system.workspace.update. Returns newest workspaces first. Parameters: status (optional: active/archived/all, defaults to active).
system.workspace.updatecoreUpdate an existing workspace's name, description, status, pin state, core team, or repository. Call this when the user wants to rename, archive, pin, or reconfigure a workspace. Use system.workspace.list first to find the workspace id. Parameters: id (required, from system.workspace.list), name, description, status (active/archived), pinned (bool), pin_order (int), core_team (list of agent IDs), repository (git URL). Only provided fields are updated.
