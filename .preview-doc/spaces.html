Overview / Workspaces
The structural foundation, simplified

Workspaces

One container — the Workspace — holds everything for a context: tasks, memory, calendar, automations, connections, member agents. One pre-seeded default (My Workspace), named workspaces for real work, and the sidebar switcher sets the context. No abstract "spaces", no mode switcher. (Channels & Connections have their own page →)

Simplification · "Rooms"/"Spaces" → just Workspaces

One container, and context is which workspace you're in

An earlier draft had three parallel "space" tiers (User · Agent · Project) plus a global scope switcher — too many systems doing the same job. Collapse them: there is one container, the Workspace. You never pick a "scope" — the context is simply which workspace you've selected in the workspace switcher already in the sidebar.

Pick a workspace in the sidebar → that's your context. The Assistant is bound to My Workspace; team agents work in whichever workspace you've selected.

How context is decided — no switcher mode

  • Mia (your Assistant) → My Workspace; can recall across all your workspaces
  • The other base agents (Jim · Ray · Ava) → the selected workspace, and work in whichever workspace you've selected
  • Workers inherit the caller's workspace; handover stays within it
  • The sidebar workspace switcher (already in the product) is the only control — it sets the overall context

Pre-seeded

  • My Workspace — the one default; the Assistant's home; your connected accounts (email · calendar), your default tasks; team agents work here too by default
  • You create named workspaces ("Acme", "Q3 Launch") for real work — "+ new workspace"
  • Naming: code currently seeds the default as "Main" — proposed rename to default workspace "My Workspace"
Naming goes all the way down: we rename project → workspace across code, contracts and storage too — today's project_id → workspace_id, rest_projects.go → rest_workspaces.go, Project.yaml → Workspace.yaml, users/<user>/projects/ → /workspaces/, and the memory "project room" → "workspace room". A v0.1.0 migration (contract-affecting, Constraint #8), done up front so nothing downstream carries the old name. (Pages cite today's project_* names as the current code.)
Tenancy, precisely: Omnipus is a single-user self-hosted app — one user (name set at onboarding), one password. No multi-user, no RBAC roles, no tenancy. Sensitive settings (model/billing keys, channel setup, security, deletes) are protected by re-typing the same password — a sudo-style confirm, not a second credential or admin account. owner=username (#406) survives only as attribution ("you" vs which agent created something), never an access gate. Workspaces, agents, memory and tasks are simply yours — nothing is hidden or access-gated.
