The target model

One coherent stack

Everything hangs off one spine: a Workspace (keyed by owner, #406, already real — single user, so owner is attribution, not a tenancy boundary) → the substrate (agents, connections, tasks, calendar, automations, memory), all keyed the same way. Context is agent-bound and set by the existing sidebar workspace switcher.

🗂 Workspaces — My Workspace (default) + named workspaces
one container · pre-seeded My Workspace (PA: email/calendar/personal tasks/accounts) + your named workspaces · single user, so the Workspace is just context, not a tenancy line
🤖 Agents — 4 base agents over a sub-agent tier, bound to a workspace
Base agents — Mia · Assistant ⭐ · Jim · Orchestrator · Ray · Scout · Ava · Builder (chat targets, full citizens) · Sub agents (workers, each with an executor — native · external-cli · future remote-a2a — inherit the caller's workspace; not chat targets) · agent-private memory = a per-agent room (agent-global); the shared room per workspace
🔌 Connections · 🗓️ Calendar · ⚡ Automations · 🧠 Memory · 🤝 Delegation graph · 🛠 Tools/providers · 🧩 Plugins/marketplaces
the shared substrate — every entity carries its Workspace; delegation & routing run on top
🔗 Protocols — layered, shapes hooked in v0.1.0
MCP (agent→tools — have, pkg/mcp) · ACP (host→coding-agent — CLI floor now via the bidirectional ExternalAgentRunner, protocol later) · A2A (agent↔agent — agent-reference + Card-identity hooks now, protocol v1.0.0). Defer the behaviour, reserve the shape; A2A wire is external (Constraint #8 untouched)
The single idea: one container, the Workspace, is the key for tasks, memory, calendar, connections and automations alike — and context is agent-bound, set by the existing sidebar workspace switcher (My Workspace + named workspaces). The data spine (owner=username) already exists — the work is to formalize it and give it a UI. Memory is self-improving, no embeddings — see Learning. Agents · the canonical taxonomy

Four base agents over a sub-agent tier

⭐ Base agents

Four named roles — Mia · Assistant ⭐ (default; memory-rich personal front door) · Jim · Orchestrator (planner/PM; supervises tasks over a blocked_by DAG + delegation graph, Max-parallel, worktrees) · Ray · Scout (research & summarize) · Ava · Builder (agent & skill authoring). Full citizens: chat · heartbeat · own connections · full memory · default-★ · can delegate, work across workspaces. Max is retired from base — automation is a platform surface, not a persona (an optional ops/automation pack later). cores exist · detail.

⚙️ Sub agents

A separate roster section — workers; the unit of fan-out. Each carries an executor: native · external-cli (Claude Code · opencode · Codex) · future remote-a2a. Deliberately stripped: no heartbeat · no own connection/identity · ephemeral memory (run-log, no continuity) · not chat targets (invoked only via delegation — a "test run" button is the exception) · not default-★ · depth-limited · a leaner/cheaper model. A tool you point at work, not a colleague. new tier · detail

The roster splits into base agents and sub-agent workers (made explicit in v0.1.0). Beyond the base — Maker/creative-media · ops · smart-home · other specialists — ships as marketplace agent packs, not built-in cores.

The sequencing rule

Front-load the shapes; add behaviour on top

The expensive refactors in this codebase are wire-format, scoping-key and config-shape changes. So we make all of those once, in v0.1.0 — most additively, plus the one deliberate breaking migration (Connection-as-instance config shape) done up front. Every later release then adds behaviour or lifts a cap — it never re-cuts the foundation.

v0.1.0 locks the shapes (additive + one migration)

  • Additive: the Workspace scoping key on tasks/memory/calendar/connections (My Workspace pre-seeded; the sidebar workspace switcher already sets context); single-user onboarding — one password, sensitive settings re-type it (sudo-style)
  • Additive: the base / sub-agent roster split (4 base agents + an executor-bearing worker tier) + delegation-policy contract type (to · modes) + the "Max parallel agents" setting
  • Additive: task fields — start · due · recurrence · blocked_by (nullable)
  • One deliberate migration: Connection-as-instance — config shape one-field-per-type → list (capped at one), new credential keys, openapi ChannelEntry/ChannelConfigureRequest change

…so later releases only add behaviour

  • multi-instance = lift the cap (the breaking config migration already happened in v0.1.0 — v0.3 just raises the per-type limit)
  • the My Workspace + PA capabilities — pre-seeded, PA features light up here (additive)
  • calendar/automations = fill the shapes (dates, deps, rules)
  • the v0.1.0 UI is real — it sits on real shapes, not placeholders
