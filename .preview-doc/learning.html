Self-improving memory · no embeddings

Memory that learns — without a vector model

Today's memory already stores across four artifacts and reflects on idle (an LLM recap writes continuity + a retro) — but it doesn't rank, relate, dedup, share, or distill across sessions. The redesign adds that learning layer: five deterministic loops + a nightly cross-session distillation, recalling across vocabulary without a single embedding. Grounded in today's pkg/agent/memory.go + session_end.go and memory-redesign-2026-05.md (D1–D22).

Today · as-is (verified in code)

What we already have — more than a file

The current system (pkg/agent/memory.go + session_end.go) is a real multi-artifact store with idle-time reflection. It's a capable foundation — the redesign adds the layer it lacks.

✅ Storage & tools — already here

  • Four artifacts (not one file): long-term MEMORY.md (3 categories) · daily notes memory/YYYYMM/ · LAST_SESSION.md · per-session retros sessions/…/_retro.md (memory.go:24-27)
  • Three tools: remember · recall_memory · retrospective
  • recall searches across all artifacts (substring, newest-first, cap 50)

✅ Idle-time reflection — already runs

  • A per-session idle ticker → CloseSession("idle") → an LLM recap (light model) → LAST_SESSION.md (auto-injected continuity) + a structured retro (loop.go:790-817 · session_end.go)
  • Heuristic fallback retro if the LLM is down; a BootstrapRecapPass catches up missed sessions on boot
  • Two write paths: volitional (remember/retrospective) + mechanical (auto-recap on idle)
What it lacks — the real gap: no ranking (substring, cap 50) · no revision (supersedes) or dedup · no graph / relationships / MOCs · no confidence/access scoring · per-agent only (no project sharing) · and the recap reflects on one session, not a cross-session distillation. Long-term lives in one MEMORY.md under a single mutex. So it remembers and reflects — it doesn't yet rank, relate, dedup, share, or distill. (bleve isn't a dependency yet.)
Tomorrow · the engine

Five compounding loops — all integer math, no ML

Self-improvement is structural, not statistical. Each loop is cheap, deterministic, and replayable.

1
Refinement, not append. remember(supersedes=X) marks X superseded; default search hides it. Agents revise beliefs instead of stacking contradictions. (D-loop 1)
2
Access counters. When a recalled memory is cited in the agent's text, an access event appends to counters.jsonl. Frequently-useful memories rank higher over time. Atomic JSONL appends — multi-agent safe, no row locks.
3
Confidence drift. Acting successfully on a recalled memory → +0.05; contradicted via supersedes → −0.20. Below 0.2 with no access in 90 days → auto-archived by a non-blocking sweep. Memory forgets the stale.
4
Conflict / near-dup detection. On every remember(), a MinHash signature is checked against active memories (60% first-line / 50% body + shared-tag thresholds). High overlap → "looks like [[existing-id]] — update that instead?" Stops duplicate drift before it starts.
5
The Dreamcatcher — distillation. Where today's recap reflects on one session, this distills across many. Nightly for workspace rooms (03:00, configurable), on-demand for private. Reads recent sessions + learnings, asks an LLM "what durable memories should I extract?", writes proposals to proposals/; an operator or agent accepts via the SPA → it becomes a real memory through remember(). Sessions become memories over time — and it proposes new topic hubs (MOCs) when a tag cluster emerges. This is the one LLM-in-the-loop step, and it's human-gated.
The hot path is regex + arithmetic + BM25 + atomic JSONL appends. An LLM is touched only at session-close (one recap call) and in the Dreamcatcher (nightly, gated). Same inputs → same memory. Auditable and replayable forever (until compaction).
Procedural memory

Skills are the editable arm of self-improvement

Memory has two halves. Declarative memory — facts, learnings, sessions — is the memory rooms above. Procedural memory is the skills the agent authors and refines: the how-to that compounds with use.

A skill created once is dead; a skill refined after each use is learning. The self-improvement loop rests on editing skills, not one-shot creation — the edit verb is the loop.

The Dreamcatcher proposes skills, not just memories

The same learning loops that distill sessions into memories watch for repeated workflows: "you've done this 3× — codify it as a skill?" (create), and later "this skill half-failed — refine it" (edit). Procedural memory compounds the way declarative memory does — by revision, not accretion.

The mechanism — author & version

  • New system.skill.create + system.skill.edit tools — the agent writes & refines its own skills (procedural memory), wired to the learning system
  • Consent-gated + versioned writes — every create/edit is reviewable and rollback-able
  • The default skill-authoring skill (create · edit/refine · validate · version · deprecate) replaces one-shot skill-creator
Today's gap: only system.skill.{install,remove,search,list} exist — and as stubs. There is no authoring or editing verb — the agent can fetch and run skills but cannot write or refine them. Authoring/editing is the missing self-improvement verb.
Phasing matches the rest of this page: the system.skill.create/.edit tool surface is a v0.1.0 shape; the learning-loop consumer — the Dreamcatcher proposing skill create/edit from repeated workflows — is v0.2.0 behaviour over it.
The hard part, solved cheaply

Recall across vocabulary — with no embeddings (D20)

An embedding model would catch "kernel safety" ≈ "Landlock". We get most of that practical recall three other ways — deterministically.

① LLM query-rephrase loop

On a weak hit, the agent re-asks with synonyms — a query-expansion loop. Free in an agent system; the model is already in the loop.

② Graph traversal

[[wikilinks]] + shared #tags bridge vocabulary islands. recall walks up to N hops over the in-memory edge map.

③ MOC navigation hubs

Maps-of-Content cluster related concepts so a near-miss query still lands on the right neighbourhood.

The search stack (pure Go, no CGo, no SQLite)

  • bleve v2 — BM25 ranking + MoreLikeThis + markdown-aware tokenizer (D16)
  • MinHash (ekzhu/minhash-lsh) — near-dup signatures, ~128 B each (D21)
  • recall rank = a pure formula: tag×4 + bm25 + log(access+1) − days×0.01 + 0.1·joint
  • Derived index is rebuildable from the .md source — blow it away and re-index

Why no embeddings is the right call

  • Determinism > fuzziness — auditable, replayable, no model dependency
  • No vector store, no ML runtime — fits single-binary / pure-Go (Constraints #1–#2)
  • The graph + tags + MOCs compensate for semantic search
  • Upgrade path is one schema change — bleve v2.6+ already does vector + RRF hybrid if real gaps appear
The substrate

A deterministic graph — and no cold start

Six edge types, each with a fixed creation rule (no inferred or similarity edges, D9). Stored as JSONL + the bleve index; rebuildable; Obsidian-native.

.omnipus/.index/                 derived, rebuildable — never source of truth
├── bleve/         BM25 + MoreLikeThis full-text index
├── edges.jsonl    links_to · tagged · authored_by · supersedes · born_in · cited_in
├── counters.jsonl access / confidence-drift event log (append-only)
├── tags.json      tag → memory-ids
└── minhash.jsonl  near-duplicate signatures

Cold-start solved — 6 seeded MOCs

Every project starts with home · decisions · lessons · people · references · goals — domain-neutral hubs (D12). The graph is never empty. The Dreamcatcher auto-proposes new topical MOCs as tag clusters emerge.

Source of truth = markdown

One .md file per memory (atomic temp+rename). Indexes are derived. No schema migrations ever. Workspace rooms are PR-able — per-file git diffs; git is the multi-agent sync layer (no server, no merge daemon).

Where it lands

Phasing — it builds on the room topology

The memory redesign reuses the room topology from the Workspace/sandbox foundation, then layers the engine and the learning loops. It sequences cleanly into the foundation-first plan.

v0.1.0 Structure + start the logs

  • Room topology — private per-agent agents/<id>/.omnipus/ + shared <workspace>/.omnipus/ dirs (all tied to the Workspace key)
  • The full memory file format (every frontmatter field present even if unused → files never migrate) + the 3 tools (remember/recall/retrospective), replacing monolithic MEMORY.md — kills the mutex bottleneck
  • bleve FTS recall (BM25) — a usable read
  • Start the append-only logs (sessions/ firehose · counters.jsonl access/citation · born_in/cited_in) so v0.2 ranking/graph have history — no backfill

v0.2.0 Behaviour over derived data

  • The 4 ranking/dedup loops (counters · drift · supersede · MinHash) + the Dreamcatcher = the five — ranking by access/drift
  • The graph (6 edges · tags · 6 seeded MOCs) + graph-aware recall + MOC auto-emergence
  • The Dreamcatcher distillation as a scheduled automation (nightly trigger → distill action)
  • All derived & rebuildable from the v0.1.0 sources + logs — no migration

v0.4.0 Assistant

  • The Assistant leverages memory: its agent-global private room + workspace-room recall = "knows you across your workspaces"
  • Promotion (private → project), multi-agent project-room writes mature with real use
The rule: structure + logs are foundational (v0.1.0) — source shapes and append-only event logs start now so nothing needs migrating. The learning engine reads derived, rebuildable data (indexes, graph map, ranking), so it defers cleanly to v0.2.0 with zero refactor — blow the index away and re-derive from the v0.1.0 sources + logs.
The room concept itself — two rooms, private per-agent + project shared — is on the Memory page. This page is the learning engine that runs inside those rooms.
