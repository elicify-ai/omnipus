Deep dive

By area

1 · Data model & contracts

Contract-first (Constraint #8) — schema → generated Go/TS → handlers. Additive changes are low-risk:

  • Task: +start_date · due_at · recurrence (nullable → safe migration). BoardTask.yaml + struct.
  • Connection: channel config struct-per-type → list of instances {id, identity, agent_binding, secret_ref}. Breaking config shape + a migration.
  • Calendar / Automation / API-key: new entities + schemas.

2 · Channels → multi-instance biggest

The cross-cutting one. Today: one instance per type, keyed by type name everywhere.

  • Wire / contract (Constraint #8): the change is in OpenAPI — the channel schemas (ChannelEntry / ChannelConfigureRequest) carry an instance id → regenerate Go/TS.
  • Config (config.go:774): one field per type → instance lists. Breaking config shape + a migration.
  • Manager (manager.go:582-708): hardcoded if-ladder → loop over instances; map keyed by instance id (:113).
  • Bus (bus/types.go): add an instance_id field — but these are in-process Go structs, not in asyncapi.yaml; it's an internal change threaded through dispatch + every channel send, not a wire change.
  • Credentials (channelCredKey, rest.go:2090): cred key per instance.

3 · Workspaces — unify the prior User/Agent/Project tiers

Single-user shrinks this sharply: #406 already stamps owner=username on sessions/tasks/projects, and with no multi-user / tenancy build there's no per-user isolation, no canAccess filtering to write. The work is the Workspace scoping key + grouping the data spine that already exists.

  • One container — the Workspace — is the scoping key; collapses the three prior tiers, no new "space" entity.
  • owner is attribution, not an access axis — single user, so no owner-spine ACL, no admin-override, no team-shared / SaaS layer to build.
  • Context is agent-bound, set by the existing sidebar workspace switcher; workers inherit the caller's workspace.
  • One pre-seeded default — My Workspace (Assistant + your accounts); named workspaces for real work. No separate Personal/General.
  • Agents are workspace members; Calendar & Connections gain a workspace tag.

4 · Automations / events

The EventBus is a real pub/sub; the gap is that domain events aren't on it.

  • Emit latent transitions onto the bus (start: task_status_changed — contract slot exists, no producer).
  • A rule-matcher subscriber (Trigger→Action).
  • Generalize cron action (prompt → also run-task / send-to-connection / webhook-out).
  • Outbound webhooks = a bus subscriber → signed POST + retry/log.

5 · Email & Calendar →

Both greenfield but pure-Go & well-trodden.

  • Email Tier-1: IMAP poll + SMTP (no CGo), one mailbox (your address + app-password). Thread = session. Ships v0.1.0.
  • Calendar import: golang-ical + rrule-go, ICS read-only.
  • Provider OAuth (Gmail/Google Cal, MS Graph): token refresh, watch renewals (7-day), 410 resync — the heavy lifecycle.

6 · Security — single-user, password-gated spine exists

  • No tenancy. One user, one password — no RBAC, per-user isolation, or owner-spine ACL to build; owner stays attribution.
  • v0.1.0 work = a password re-type gate for sensitive settings (sudo-style), mapping straight onto the existing RequireNotBypass guard + auth tree — small, contained.
  • Delegated OAuth (later) = high blast-radius (agent acts with your Google): scopes, consent, vault, allow/ask/deny on writes, audit.
  • Inbound webhook + email = untrusted command surface (HMAC #162, sender allowlist, DMARC/SPF).
  • Scoped API keys (later) = least-privilege vs today's full tokens.

7 · UI / Information architecture ship the shell early

The IA changes are the cheapest part and the highest-leverage to do first (so nothing moves later):

  • Rename Channels → Connectors; show instances + identity
  • New Calendar surface (per-workspace · All + 4 filters)
  • New Automations surface (Schedules reframed)
  • Context via the existing sidebar workspace switcher; pre-seed My Workspace
  • Tasks gain visible date / repeat fields
  • Settings: connected accounts · API keys · integrations

Plus three small v0.1.0 adds: single-user onboarding (name + one password + a model key); a password re-type on sensitive settings (reuses RequireNotBypass); the 4 base agents (Mia · Assistant ⭐ · Jim · Orchestrator · Ray · Scout · Ava · Builder) over a sub-agent/executor tier (additive agent kind, Assistant auto-provisioned; specialists as packs); and a "Max parallel agents" control in Settings → Performance (CPU/RAM recommendation + over-limit warning) — low effort, and a stabilization win on fan-out.

8 · Memory — rooms + self-improvement upgrade today's store

Upgrade today's multi-artifact store (MEMORY.md + daily notes + last-session + retros + idle-time recap; pkg/agent/memory.go · session_end.go) to two rooms — a private room per agent (agent-global) + a workspace room shared across a workspace — plus bleve ranking, the graph/MOCs, cross-session distillation, and workspace sharing (the self-improving Learning engine). recall composes private + current workspace.

  • 5 self-improvement loops: refinement / supersede · access counters · confidence drift · MinHash conflict · the Dreamcatcher nightly distillation.
  • Graph: 6 edge types + 6 seeded MOCs; query-rephrase + graph + MOCs do retrieval — no embeddings.
  • Pure-Go, no SQLite (Constraints #1–2): bleve BM25 + MinHash; bleve is a new dep (not in go.mod today).
  • Wire / contract: new memory file format + 3 tools; the bleve index is a new dependency.

9 · Tools & multimodal providers exist · TTS/image new

Tools are per-tool pluggable providers — and the pattern is already proven: the SearchProvider interface (Brave/Tavily/Perplexity/SearXNG/GLM/Baidu) and the voice-in Transcriber interface (Groq/ElevenLabs/audio-model) plus vision (image-in) all ship today. The new work is to extend the same shape and surface it.

  • Cheap (surface what exists): the Integrations provider-picker UI over the existing search + voice-in backend + a mic in chat — v0.1.0.
  • New interfaces: Synthesizer (TTS — per-agent voices) + voice playback + ImageProvider (image-gen) — v0.2.0.
  • Sovereignty: API default + optional local sidecar (Piper / whisper / SD / SearXNG); per-agent provider overrides + image edits/variations + realtime voice — v1.0.0.
  • Wire / contract: two new provider interfaces + the Integrations UI; the existing providers are already multi-backend. See ToolsTool CatalogPlugins.
Sequencing

Critical path & the one big rock

The single high-risk, high-blast-radius item is multi-instance connections. The wire-format change is in OpenAPI — the channel schemas (ChannelEntry / ChannelConfigureRequest) — plus the breaking config.go:774 shape migration and per-instance credential keys; the bus instance_id is an internal Go-struct field, not an asyncapi change. Per-agent bots, the Email channel, and the Personal Assistant all depend on it. Everything else (calendar, task dates, automations spine, iCal import, the whole IA shell) is independent and lower-risk — so it ships first while the instance-id work is designed carefully.

Independent & low-risk (do now)

  • Single-user onboarding + password re-type gate
  • 4 base agents (Mia·Assistant⭐ · Jim·Orchestrator · Ray·Scout · Ava·Builder) + sub-agent/executor tier + auto-provisioned Assistant; specialists as packs
  • "Max parallel agents" setting (stabilization)
  • Basic IMAP/SMTP email (one mailbox)
  • Task dates + recurrence
  • Calendar + iCal import
  • Automations spine (events + rules)
  • The full IA shell (workspace switcher, Calendar/Automations/Connectors surfaces)

Gated on the instance-id rock

  • Per-agent chat bots
  • Multi-mailbox email (per-agent identity) — basic one-mailbox email is independent, ships v0.1.0
  • Personal Assistant capabilities (user-identity connections)
  • Generic webhook channel
