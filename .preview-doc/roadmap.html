Overview / Roadmap & release plan
How we ship it · v0.1.0 → v1.0.0

Roadmap & release plan

v0.1.0 is the foundation — it lands every structural shape (additive) plus the one deliberate Connection migration, done up front, and stabilizes the build. Every release after only adds behaviour or lifts a cap. The foundation is never re-cut.

The governing rule

Front-load the shapes, defer the behaviour

The expensive refactors here are wire-format, scoping-key and config-shape changes — each ripples through generated types, storage and UI. So we make all of them once, in v0.1.0: most are additive and behaviour-constrained (new nullable task fields, agent kind, a delegation-policy type, the Workspace scoping key), plus the one deliberate breaking migration — the Connection-as-instance config shape (one-field-per-type → list, new credential keys, the openapi ChannelEntry/ChannelConfigureRequest change). Doing that one migration up front is the thesis. Later releases lift caps and fill behaviour against shapes that never move.

The old trap (avoided)

  • Ship a "Connectors" list over a still-singleton backend → rebuilt at multi-instance
  • Ship an empty Calendar shell → rebuilt when data lands
  • Defer the Connection config migration → it hits a feature release as a breaking change

The rule (followed)

  • Do the Connection-as-instance config migration now (cap at one) → v0.3 just lifts the cap, no second reshape
  • Land the Workspace key + pre-seeded My Workspace now → v0.4 just lights up the My Workspace's PA features
  • Land optional instance_id on the in-process bus structs now → later releases populate it
  • Derived data (indexes, graph map, ranking) is rebuildable → free to defer; persisted shapes + append-only logs start in v0.1.0
Each release strictly builds on the one before — no release reshapes an earlier one's data.
The foundation

v0.1.0 · Foundation — lock the shapes, ship the IA, stabilize

Deliberately shape-heavy and behaviour-light: additive schema + an IA shell that sits on real data + the existing engines surfaced. Low runtime risk; maximum structural runway.

Shapes — additive + one migration

  • Additive: Workspace scoping key on tasks/memory/calendar/connections (My Workspace pre-seeded; the sidebar workspace switcher already sets context)
  • Additive: agent kind + nullable voice field · the full delegation-policy contract (to · accept_from · modes · depth · budget) — complete schema; only to+modes enforced now, accept_from/budget later
  • Additive: task fields start · due · recurrence · blocked_by (nullable)
  • Memory structure + start the logs (tied to the Workspace key): room topology (private per-agent agents/<id>/.omnipus/ + shared <workspace>/.omnipus/) + the full per-memory file format (every frontmatter field present even if unused → files never migrate) + 3 tools (remember/recall/retrospective) replacing monolithic MEMORY.md + bleve FTS recall + start the append-only event logs (sessions/ firehose · counters.jsonl access/citation · born_in/cited_in capture) so v0.2 ranking/graph have history and never need a backfill
  • Procedural memory — wire the skill tools: connect the stub system.skill.* tools to the real pkg/skills engine + add system.skill.create/.edit (the authoring capability — the self-improvement verb; consent-gated + versioned) · embed the default skill set (summarize · skill-authoring · plan · daily-briefing) via go:embed + first-boot seed — see Learning
  • One migration: Connection-as-instance — config one-field-per-type → list (cap one), new credential keys, openapi ChannelEntry/ChannelConfigureRequest change
  • optional instance_id on the in-process bus structs (Go field — not a contract change), defaulted
  • Additive: the ExternalAgentRunner interface is bidirectional + consent-routed + resumable (ACP-ready, and the CLI floor needs it too — stream-json + permission-prompt + --resume)
  • Additive: the work-target is an agent-reference (delegation to + sub-agent executor admit a future remote-a2a kind) + Card-projectable agent identity (stable id + declared skills → a future A2A Agent Card; no new fields)
  • Extensibility shapes — the plugin bundle manifest (component-level hybrid: reuses SKILL.md + .mcp.json, native agents/channels/providers) + the marketplace-provider list (RegistryConfig single→list — the same one-time refactor as Connections/tool-providers). Installer + Marketplaces UI deferred. See Plugins

IA shell + onboarding

  • Single-user onboarding — "what should I call you?" + one password + add a model key
  • One-password auth — sensitive settings re-type the password (sudo-style; maps onto RequireNotBypass)
  • the existing sidebar workspace switcher (My Workspace + named workspaces) — sets agent-bound context
  • Connectors (Channels renamed) — instance list, one per type
  • Tools → Integrations provider-picker (search · voice-in already multi-provider — just surfaced) + a mic in chat (voice-in) — see ToolsPlugins
  • Calendar — shows real tasks · schedules · milestones

Roster, agents + stabilize

  • Four base agents (re-cast cores) — Mia · Assistant ⭐ (default front door) · Jim · Orchestrator (planner/PM) · Ray · Scout (research/summarize) · Ava · Builder — plus the sub-agent worker tier (additive kind + executor). Max retired from base (automation = platform surface; optional pack); specialists arrive as marketplace packs
  • Preinstalled set = the 4 base agents + 3 runner drivers (Claude Code · opencode · Codex) — everything else via packs
  • "Max parallel agents" setting (Settings → Performance) — CPU/RAM-aware recommendation + over-limit warning
  • Delegation trust-graph (simple) — close the two ungated work-paths (handover stays open)
  • Basic IMAP/SMTP email — one mailbox (your address + app-password, pure-Go)
  • Green CI; harden channels / tasks / schedules / chat — rendering, security, resilience fixes already landed
Why it's safe and foundational: nearly every shape is additive (nullable fields, agent kind, new contract types, the Workspace key) — they prepare structure without changing runtime behaviour. The one exception is deliberate: the Connection-as-instance config migration (one-field-per-type → list, new credential keys, openapi change), done once, up front, so v0.3 only lifts the cap. The risk surface is schema + migration correctness, which is testable. The UI is real, not placeholder — see UI Changes.

Where it fits

Against the existing strategy

v0.1 / v0.2 (old) ✅

The prior internal increments — iframe-preview unification, sandbox/exec, pentest hardening — were pre-release hardening. They fold under the new line as already-shipped groundwork.

v0.3 "Rooms" → "Workspaces" 🚧

The locked Rooms/memory/tasks/sandbox redesign is generalized into the one-container Workspace model and spread across v0.1.0 (shapes) → v0.4.0 (My Workspace + PA), each with a UI home.

The 1.0 line 🎯

A single climb: stabilized v0.1.0 → complete vision v1.0.0 (Workspaces · Connections · Calendar · Automations · Assistant · Delegation · open integration).

Release numbering: the prior v0.1/v0.2 were pre-release hardening increments; the product line now re-baselines on one climb to 1.0 — the stabilized build ships as 0.1.0, each release adds one capability layer to 1.0.0.
Decisions captured

Locked so far

  • Foundation-first sequencing — every structural shape lands in v0.1.0: additively, plus the one deliberate Connection-as-instance migration (config shape + credential keys + openapi) done up front; later releases add behaviour / lift caps only
  • Single user, one password — no multi-user, RBAC, or tenancy. One person, one password protects the install; sensitive settings re-type the password (sudo-style, mapping onto the existing RequireNotBypass guard). owner stays as attribution on data, not an access-control axis.
  • Agent roster — four base agents (re-cast cores: Mia · Assistant ⭐ default · Jim · Orchestrator · Ray · Scout · Ava · Builder; Max retired → automation is a platform surface / optional pack) plus a sub-agent worker tier (additive agent kind + executor). Preinstalled = the 4 base agents + 3 runner drivers (Claude Code · opencode · Codex); specialists are marketplace packs
  • "Max parallel agents" setting (Settings → Performance) — a CPU/RAM-aware recommendation with an over-limit warning; a stabilization guardrail on fan-out
  • Rooms → one container, the Workspace; context is agent-bound, set by the existing sidebar workspace switcher (My Workspace + named workspaces). Pre-seeded My Workspace (the single default); memory is 2 rooms — a private room (per-agent, agent-global) + a workspace room (shared); recall composes the agent's private room + the current workspace room. My Workspace ships v0.1.0; the My Workspace's PA features light up in v0.4.0
  • Memory: two rooms (private per-agent · workspace shared); no embeddings (bleve BM25 + graph + MOCs); the Dreamcatcher distills sessions→memories — see Learning
  • Channels → multi-instance Connections (identity = agent | user); the instance config shape migration ships v0.1.0, the cap lifts v0.3.0
  • Agents: two tiers — base agents (the four re-cast cores + custom; you chat with them, heartbeat, own memory, can delegate) and sub-agent workers (general-purpose worker + custom, carrying an executor: native | external-cli {Claude Code · opencode · Codex} | future remote-a2a; no heartbeat · ephemeral · delegation-only)
  • Delegation: v0.1.0 unifies the two allowlists into one policy (to · modes), ships the simple trust-graph UI, and closes the two ungated work-paths (sync subagent · sequential — handover stays open). accept_from + budget/concurrency land when enforced later. Dependency sequencing via blocked_by deps; coordinator/autonomous plans are v1.0.0.
  • Personal Assistant: the agent auto-provisioned at onboarding, bound to your My Workspace; its deeper PA capabilities light up v0.4.0
  • Email: basic IMAP/SMTP (one mailbox, your address + app-password, pure-Go) ships v0.1.0; multi-mailbox v0.3.0; provider OAuth (Google → MS Graph) v1.0.0
  • Calendar + Automations: shapes & shells v0.1.0, live v0.2.0; integration v1.0.0
  • Tools = per-tool pluggable providers (search + voice-in exist; TTS + image-gen + Integrations UI are new); split: Integrations+mic v0.1.0 · voices+image v0.2.0 · realtime v1.0.0 — see ToolsPlugins

Next step when you're ready: an ADR (/albert) on the Workspaces + Connections + agent-taxonomy + delegation model, then a phased plan-spec starting with v0.1.0.
