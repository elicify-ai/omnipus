Agent work folders & memory

The locked design (memory-redesign-2026-05.md) is two rooms: a private room per agent (agent-global) and a shared room per workspace — the spec calls this the "workspace room" (a workspace's shared room). This page is the room concept; the Learning page is the self-improving engine that runs inside them. Sessions are stored per-agent (agents/<id>/sessions/) and carry a workspace_id tag — "the project owns its conversations" means a filtered view, not physical partitioning. Today memory is ~90% built: two-room topology, full per-memory file format, remember/recall/retrospective tools, append-only logs, bleve BM25 index — the workspace-tag filtering and bleve-wired recall are the remaining 0.1.0 gaps.

Foundational — structure now, behaviour later. The room structure (topology + file format + tool contracts) is a v0.1.0 shape tied to the Workspace scoping key (refactor if deferred); the append-only logs (counters · edges.jsonl · tags.json · minhash) start in v0.1.0; bleve BM25 recall is wired in v0.1.0 (index already built). The learning behaviour (ranking · graph · MOCs · 5-loops · Dreamcatcher) is v0.2.0 over derived, rebuildable data — no migration. See Learning.
The structure · two rooms

Private (per-agent) & Workspace room (per-workspace)

Memory is scoped to a room (D17). Each agent has one private room — its own, spanning all its work (agent-global). Each workspace has one shared room — the spec's "workspace room" — written by its member agents and attributable by author. That's it — two rooms, one format, one set of tools.

Two rooms. Sessions live in the agent's private room (agents/<id>/sessions/) and carry a workspace_id tag — filtered per-project, stored once. An agent writes memories to its private room by default; in a workspace session it writes to that workspace's shared room (D18). The Assistant's agent-global private room is what lets it "know you" everywhere — no special store needed.
The key distinction

Persona is global; memory lives in rooms

This untangles "agents are shared but memory must be scoped." Separate the reusable agent from its memory.

🎭 Agent persona — global, reusable

The identity: AGENT.md · SOUL.md (prompt) · HEARTBEAT.md · skills · model · tools. One "Mia" persona, available to everyone. Not memory. Lives in the agent registry (core agents, or user-owned custom).

🧠 Agent memory — in the rooms

What the agent has learned: its private room (its own, agent-global) + the workspace rooms it's a member of. The persona is the same everywhere; the memory differs by room. remember/recall/retrospective are the only writers/readers.

Memory has two halves. Declarative memory — the rooms on this page (facts · learnings · sessions). Procedural memory — the skills the agent authors & refines, its editable how-to. The detail lives on Learning.

Default scope follows context (D18)

  • Workspace session → remember() writes the workspace room
  • Otherwise → writes the agent's private room
  • remember(scope=private) → agent's cross-workspace bank (agents/<id>/.omnipus/) — read in every workspace
  • recall = current workspace room + the agent's private bank; the Assistant additionally wide-reads all owned workspace rooms

Multi-agent workspace rooms

  • Three agents, one workspace room; each keeps its private room
  • author is set on create, never mutated — ownership is informational
  • Counters via append-only counters.jsonl (no frontmatter contention); body edits via per-file flock + etag
  • git is the sync layer — commit <project>/.omnipus/memories/*.md; no server, no merge daemon

recall() = current workspace room + the agent's private bank

Personal assistant · Mia

Mia's private bank (scope=private memories) holds cross-workspace learnings — "knows you" everywhere. In My Workspace she reads My Workspace room + private bank; in Acme she reads Acme room + private bank. As your primary assistant she also wide-reads all workspace rooms you own. Sessions in all workspaces live in agents/mia/sessions/, each tagged — per-project continuity = resuming the last session tagged for that workspace.

Concrete

The on-disk layout

Per spec: the private room is agents/<id>/.omnipus/ (agent-global); the workspace room is <project>/.omnipus/ (the workspace dir, inside the workspace tree so git can sync it). All workspaces are the single user's.

Storage tiers (D3/D4)

  • memories/ — semantic, via remember()
  • learnings/ — reflective, via retrospective() or auto-recap
  • sessions/ — episodic firehose (every turn); each session tagged with workspace_id
  • last-session.md — auto-injected each session; per-project continuity = last session with that workspace tag

Work-folder (sandbox) rules

  • Cwd = the current workspace folder; private scratch in the agent's workspace dir
  • Kernel grant per turn: RW agent-private + RW current workspace + R-only system
  • Sessions + last-session are per-agent (not per-workspace) — tagged with workspace_id for filtered views; a session may carry >1 tag
  • The learning engine (loops · Dreamcatcher · no-embeddings) → Learning
Locked decisions

Key decisions (2026-06-21)

  • Sessions per-agent, workspace-tagged (not per-workspace): sessions are stored in agents/<id>/sessions/ and carry a workspace_id tag. "The project owns its conversations" means a filtered view. A session may carry >1 workspace tag (cross-project chats stored once, tagged for both). Per-project continuity = last session with that tag.
  • Private room = cross-workspace memory bank: remember(scope=private) writes to agents/<id>/.omnipus/ memories/learnings; these are read in every workspace. Default remember() writes the current workspace room.
  • recall = workspace room + private bank: the Assistant additionally wide-reads all owned workspace rooms. No separate user-facts store — "about you" lives in the Assistant's private bank.
  • "About you" facts: live in the Assistant's private bank (scope=private) — not a separate user tier. Any agent may write a workspace memory with explicit scope=project.
  • Custom-agent personas: global registry with an owner field (today's AgentConfig.OwnerUsername) — unchanged.
  • Migration: the legacy flat agents/<id>/memory/MEMORY.md is not migrated (fresh-build, D2); the new room layout starts empty.
